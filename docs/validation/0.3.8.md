# 0.3.8 拖动开销与可见跟随动画

用户反馈：拖动节点CPU占用明显提高，上一版承诺的动画没有在正常拖动时看到。静态排查确认旧路径每次pointermove更新AtlasPane工作副本状态、重绘整个阅读页及隐藏测量节点，同时重算端点排序；动画hook在dragging分支直接返回目标布局，因此普通拖动没有位移过渡。

本轮改为：

- NodeCard将高频移动合并到requestAnimationFrame，释放时补齐最终指针位置再提交，取消/卸载清理待处理帧。
- MapScene局部保存拖动预览，AtlasPane实时更新工作副本引用及会话保留资料，仅开始/结束时更新界面状态；保存仍在释放时通过原服务执行。
- 拖动预览复用端点顺序，不重跑六轮排序，释放并提交目标布局后再排序。卡片/连线使用memo，节点/关系按ID建索引；未移动对象的引用保留，减少无关DOM重绘。
- 普通拖动显示70ms的短跟随，松手/取消回位140ms收尾，节点/端点/曲线共享插值坐标。节点位置通过transform呈现，不另加CSS位置补间，降低拖动阴影开销，只有正在拖动的卡片标记will-change。
- 减少动态效果时立即更新；拖动期间冻结连接边/顺序以节省计算，跨越其他节点后在释放时统一调整，仍不启用曲线交叉搜索。
