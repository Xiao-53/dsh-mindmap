# DSH 累计回归提示词

## v0.4.1 定向验收提示词

```text
/mindmap 请验收 dsh-mindmap v0.4.1。先核对实际加载版本和可用的工具。所有写操作只在本次新建的专用验收图中进行。

1. 用 atlas_create 新建「实时预览验收」。按输入准备、内容整理、质量检查、交付四个阶段，每阶段安排 6 个有编号的验收步骤。总览保留阶段，细节放进子图或节点详情。用 atlas_read 回读，报告 mapId、各视图 occurrences 数量、24 个步骤的落点和是否有遗漏。默认每个视图最多 20 个显示节点。
2. 在「正文验收」节点准备三级 Markdown 标题、有序和无序列表、单独成行的 $$y=x^2$$、一张 x^2 函数图和一张样例统计图。保留这三行原文：`300万平方公里（$dd$常见估计）`、`- sdaf$x$`、`- *原料*产地、**销售市场**与资本输出场所`。用 atlas_read 核对正文和两个图块 ID。
3. 如果能操作并观察侧栏，进入「复制内容」旁的「编辑」。在上述三行移入和移出光标，核对行内公式与文字基线、滚动条、列表异常断行。复验空列表项回车退出、删除一个公式定界符、撤销重做和自动保存后重开。利用现有本地测试图片，在正文段间拖放并撤销，再拖到 DSH 提问框上松手，核对正文位置和草稿。从图片左侧按 Delete、右侧按 Backspace，检查整张图片引用删除及撤销。没有图片时保留该项待验。
4. 我手动发送带正文位置或图表引用的请求后，再验证定位写入。位置引用用原 anchor 提交单项 insert_note_content，图表引用按原 ID 核对快照后局部更新。用 atlas_read 给出实际落点或图表改动。若有独立 HTML 并能实际打开，检查节点详情的只读呈现。

按「通过／失败／待验」报告每项，附实际工具结果或界面观察。工具读回可作数据证据。需要我操作界面或手动发送引用的项目，给出最短步骤。保留验收图供复验。
```

## v0.4.0 累计验收提示词

适用版本 `v0.4.0`，基线 `0.3.12`，目标宿主 DSH `v0.2.2-rc.3`。加载本次安装包后，在独立验收工作区把下方代码块一次发给 DSH。之后按 DSH 的分轮提示继续手动操作。可按 [插件安装说明](../plugin-development.md) 加载 [正式安装包](https://github.com/Xiao-53/dsh-mindmap/releases/download/v0.4.0/dsh-mindmap-0.4.0.tgz)。

````text
/mindmap 请协助我验收思维导图插件从 0.3.12 到 v0.4.0 的累计功能。只在当前工作区新建一张名为「导图累计回归 · 咖啡店运营」的专用测试图，所有写操作只限这张图。每轮记录实际调用的 atlas 工具、返回状态、目标 ID 和可核对的结果。需要我操作插件界面或确认宿主授权时先停下来。计算、编写样例或工具成功都不能代替实机观察。用「通过／失败／待我操作／样例缺失」记录每项。

第一轮，准备测试图并验证内容组织。
1. 用 atlas_create 新建。给总览至少两个相邻分组，准备一个有七个分组的子图用于测试多列。请覆盖 25 个不同主题点，比如菜单、客流、原料、库存、排班、培训、质检、设备、定价、成本、收入、毛利、渠道、促销、复购、会员、外卖、评价、投诉、卫生、供货、订货、损耗、现金流、复盘。按主题分配到总览、子图及详情。创建后用 atlas_read 统计每个视图的 occurrences，检查默认单页最多 20 个、主题点都能找到。另记下只有用户明确要求同页展示时才可以超出默认数量。回报地图和节点 ID，以及各视图的显示节点数。
2. 至少准备四个节点。「运营概览」有摘要与一篇能滚动的长笔记，含 #、##、### 标题、长标题、## 简介、列表、表格、代码中的井号、中文粗体及表情。正文有三段以「行内定位」「独立定位」「图表定位」开头的普通段落，至少另留三段作为上下文。「公式与图表」有正常行内公式、独立公式、转义美元、代码内公式、函数图、柱状图和折线图。「空白笔记」无正文。「保存与冲突」专门用于改摘要、图块位置失效与外部更新验证。给「运营概览」一个从另一视图可达的同节点出现位置。
3. 公式样例使用分式、根号和求和。函数图至少包含 x^2 与 1/x，检查原点附近断开。柱状数据用 0、负值和 null。折线数据用 [1,null,0,3]。分别给三张图短标题、唯一 ID、图例和实际单位，统计数据注明是验收样例。用 atlas_read 核对首版保存数据。图片由我随后通过界面添加，可用任意本地测试 PNG。

第二轮，等我确认加载图后，逐组给我操作说明，并记录我反馈的观察。
A. 回收站基线。进回收站，分别点击「回收站」「未完成创建」，再重复点击当前项。核对列表和选中状态。需要测试还原时只用这张验收图并随手还原。有现成验收占位才检查它的清理身份和原生审批，无样例记为缺失。
B. 详情和自动保存。编辑默认由底部「编辑」打开。正常宽度和窄栏分别滚到中部再往返「编辑／完成」，核对同段仍可见，标题、摘要、分隔、正文边距和换行相同。检查三级标题颜色及层级、代码井号、列表、表格、图片和公式。测试中文组字、纯文本粘贴、标题/摘要/正文修改、图片在插入点出现并可从图片角上删除，观察自动保存、状态图标、重开及共享节点同步。只读会话需保持可阅读和复制，写入由宿主拒绝。能安全制造外部版本变化时，只用专用节点，核对失败提示、本地内容、重试或放弃。
C. 布局和历史。用「全部导图」旁控件循环纵向与田字型，在七组子图查看多列，测试重置和撤销重做。把节点拖到相邻分组背景，再拖向原分组左上方，核对拖动中、松手、保存后重开、撤销和重做时背景原位原尺寸，节点及连线跟随且原组归属可核对。取消拖动不计步。可用 31 次独立小拖动复核 30 步边界，再交叉检查详情与画布快捷键、DSH 草稿输入撤销及外部版本更新后历史隔离。实际硬件耗时和重叠数如未测量，就记待验。
D. 公式和图表。读写两态核对函数曲线、统计图、图例、缺值与公式。点击公式修改已有 TeX，检查预览、应用、取消、删除及重开。遇无法排版的公式时核对原式回退。用拖动把手移动完整图表到正文开头和末尾，检查落点、取消、围栏 ID、定义及周边正文。删除一张图等自动保存，再撤销和重做，重新打开核对磁盘。保持另一张图与正文原样。
E. 离线分享。用插件重新导出单个独立 HTML，复制到另一目录，断网打开。自由拖动有连线的画布节点，检查节点、端点和连线跟随、分组保持。切换子图再返回应保留落点。测试顶部排版图标切换纵向、田字型和多列，检查只调整当前视图，刷新后回到导出位置与排列。打开节点详情，核对选文复制、图片、公式和图表，确认详情只提供阅读操作。

第三轮，分别协助我验证 DSH 引用。本轮复验空白位置引用。文字取点时按现有段后规则验证图表。
1. 我会在提问框留一段文字、一个已有引用和一个附件，再选中一部分已有草稿。在笔记的阅读态、编辑态各选一段正文，分别用浮条「添加到正文」，并在编辑态用右键选区再试一次，核对仅追加引用，草稿原内容保留。然后从一张函数图右键加入图块引用。等我观察草稿原内容被保留、尚未发送和引用回跳。我明确发送后，请用 atlas_read 按图块 ID 核对快照，再仅改变该图一条表达式，例如把 x^2 换成 x^2+1，保留该图 ID、其他公式、图、正文和布局。另可演示 atlas_preview 删除影响，只有我在宿主批准才提交，样例仍限专用图。
2. 我会在编辑正文不同段落中右键「添加图表/公式」。每次先核对草稿保留和回跳。在窄侧栏靠近右边和底部右键，观察菜单靠近选点、按钮完整可见，打开菜单及插入图表后正文保持原来的左边距。等我分别手动发送三条消息后，再按消息执行：在实际点击字符间插入行内公式、在对应段落后插入独立公式、在另一段落后插入新图。每次重读节点与版本，将引用附带的 anchor 原样传给单项 insert_note_content。请用 atlas_read 给出前后短对照和公式或图块的确切落点。
3. 我会在有正文的笔记中分别右键段间空白、正文开头和末尾，选择「添加此位置到正文」，核对 DSH 提问框中的位置引用。等我手动发送后请按 anchor 在指定空白处新增图表，并给出两侧正文保持的根据。我也会用空白笔记的正文开头发一条加入行内公式的请求。再用另一个引用测试失效：取得引用后我先改掉所指段落并保存，再发出原请求。请记录准确的工具反馈、提示我重新选点，并核对笔记原样。如果我没有附上具体位置引用，就先停下让我在界面取点。

最终给出一张表，逐项记录基线回收站、内容组织、读写排版、输入和自动保存、图片、布局背景、历史、公式、整图操作、图块引用、正文位置引用、冲突、离线导出。把工具返回和我的实机反馈列开，标明剩余待验。保留测试图供复验。
````

三种定位引用各需一次实际手动发送。可分别使用以下短句，发送时使用 `/mindmap`，并携带刚取的「正文位置」引用。

- 在点击位置插入行内公式 `\(r=\frac{收入}{订单数}\)`。
- 在对应段落之后插入独立公式 `$$\sum_{i=1}^n a_i$$`。
- 在对应段落之后新增「验收趋势」折线图，使用类目「甲、乙、丙、丁」和数值 `[1,null,0,3]`。
