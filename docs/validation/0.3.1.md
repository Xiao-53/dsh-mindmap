# 0.3.1 管理页与回收站

本轮按用户截图精简管理页，并按后续要求统一普通列表与回收站的风格。交付包为仓库根目录dsh-mindmap-0.3.1.tgz，目标DSH版本不变。

## 操作

普通列表和回收站采用相同字体、配色、行高和`···`菜单。移除搜索框、常驻刷新/关闭按钮、展开的大块操作栏和移动下拉。重命名原地输入，移动使用拖动；所选多项和文件夹均可拖动，禁止父文件夹拖入自身或后代。列表观察工作区目录、地图结构和操作完成标记，窗口聚焦和返回页签会重新载入；仅错误状态保留重新载入入口。

默认不显示勾选框或批量按钮，点击“选择”才进入多选模式。普通列表菜单为重命名/删除，回收站菜单为还原/永久删除；回收站上方`···`提供全部还原和清空回收站。选择模式使用同一条精简操作栏，支持全选、删除所选、还原所选，点击完成退出。

删除导图直接移入回收站，支持之后还原；删除文件夹直接将其内容上移。两者均取消二次确认。用户已明确选择支持回收站永久删除所选项和清空，永久删除也不增加确认弹窗。

## 永久删除的行为

只对回收站ID开放，绑定工作区、当前目录版本及会话写策略。Host逐图进入地图队列，以active.json认领防止与内容工具并行；`.transactions/purge.json`记录从有效快照取得的具体文件及版本。先核对全部仍存在文件，再逐项条件删除，结构文件最后删，复核清单全部缺失后记为完成；不递归删目录，不删除未知文件、未引用资源或已有exports。

永久删除为不可逆操作，不回退已删除文件。权限失败或外部版本冲突时报告具体失败，成功项从回收站消失，失败项保留“删除未完成 · 可重试”，菜单可继续删除；该状态不能还原为正常地图。目录更新失败后重新载入可再次执行，完成清单避免重复删除新文件。进程中断残留active.json须确认原操作/原Host已结束，再执行既有`/minimap recover <mapId> 原操作已终止`释放认领，然后回收站继续删除；不会声称已删除内容能够恢复。
