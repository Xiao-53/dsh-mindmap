# 给 DSH 的首期加载与验证提示词

把下面代码块直接交给运行DSH的会话。当前候选为0.2.1，完整交接场景见 [人工验收清单](validation/current-candidate.md)；已接入范围和剩余功能分开记录。插件仓库指本文件所在仓库；若会话工作区不同，先明确仓库位置和用于验证的工作区。外观与动画由用户人工核对，不要求模型读取原型或计算坐标。

```text
加载并协助验证当前仓库的 dsh-mindmap 首期插件。

本次人工验收范围包括选择页和文件夹、v17图标与绘图交互、节点拖动与布局保存、节点及选文引用、问题草稿文本、全图离线HTML下载、跨层搜索、外部文件刷新和鼠标侧键返回/前进，以docs/validation/current-candidate.md为准。我会自行操作界面和手动发送消息。仅当前视图导出、预检、默认exports、稳定问题引用、撤销和多文件恢复仍为剩余功能，不要求我提前验收，也不要标通过。不要自动发送、提交或替换已有草稿，不调用不存在的atlas_*工具。

先读取 docs/plugin-development.md 的工程命令和加载步骤，以及 docs/mindmap-authoring-prompts.md 中的 JSON/Markdown 内容格式。不要读取 HTML 原型，不生成或修改界面、样式、坐标、layout.json 或恢复记录。不要运行自动测试、浏览器自动检查或代替我的手动验收。

1. 确认当前 DSH 实际版本和 profile，版本必须是 0.2.2-rc.3。确认插件仓库实际路径；使用现有构建产物 dsh-mindmap-0.2.1.tgz。不运行构建、测试或自动检查脚本；如果安装包缺失，说明缺失并交回用户处理。
2. 按开发文档，将本地 tgz 安装到已识别的当前 profile，再检查配置层是否包含 dsh-mindmap。保留已有插件和配置，不重置 profile。需要重启时，告诉我已完成哪些步骤及当前安装对应的实际重启方式，由我重启；不要结束正在运行本次会话的宿主。
3. 重新加载后检查插件的 Host、Client、dshAtlas/request 及原生“思维导图”入口是否存在。可用时使用宿主现有 Inspector；没有该工具时说明并检查实际日志，不虚构工具、命令或成功结果。不要把“安装成功”当成侧栏、引用或观察已通过。
4. 在当前已授权工作区新建一个独立验证地图，地图 ID 和目录名使用未占用的 atlas-check-加随机标识。仅为验证样本使用现有文件工具准备 map.json 与节点 Markdown，不接管或覆盖已有目录。保存成功后报告实际相对路径；插件现在支持原生创建空白导图；本步骤仍仅为验证复杂内容准备独立样本。
5. 样本包含一个根视图、至少两层子图、跨视图共享节点、两种有方向关系、同名但不同 ID 的节点、超过 12 条相同关键词命中和含可读公式及长段落的 Markdown。使用 schemaVersion=1、合法 category/icon/type 枚举；保持 childViewId 与 centerNodeId 双向一致，视图父级无环，关系的两个端点均出现在显示它的视图。不要创建 layout.json，由插件测量和补位。笔记只按简介、核心理解、关键公式 / 规则、典型示例、学习提醒按需组织。
6. 样本必须包含真实学习关系，不用孤立的“关键词校验”等测试卡片充当知识结构。逐个核对每个节点的前置、后继或补充关系与箭头方向，relationIds 包含应显示的全部关系；只有分类关系时使用分组，不伪造概念依赖。不要用两条关系的稀疏样本代表原型绘图验收。告诉我打开“思维导图”并刷新选择该样本，先确认手动打开停留在目录、空工作区出现创建引导、文件夹可嵌套和折叠、整理后重新打开目录仍保留归档，再等待我提供操作结果。我会测试拖动与连线同步、松手不下钻、重开后位置保留、滚轮缩放、搜索、下钻返回、节点／选文加入正文、问题草稿和离线 HTML。我会先保留一份含文字、引用和附件的未发送草稿；你不要帮我点击发送，也不要通过另一个模型请求代替插件引用操作。
7. 我确认准备好刷新测试后，只修改本次样本的一个节点标题或 Markdown，保留身份与其他字段，不碰布局。验证外部更新后的读取结果。需要制造无效数据时先在内存或明确的测试备份中保存原内容，仅对本次样本引入一个重复 ID 或悬空引用，报告改动并等待我的界面反馈，然后恢复原有效内容。不要对用户既有地图做故障试验。
8. 汇总实际版本、插件加载结果、样本路径、已执行检查、发现的问题和未执行项。只记录必要错误摘要，不输出凭据或整段会话。真实草稿保留、重载后引用恢复、窗口尺寸、动画时长和首次使用者试用仍须以我实际操作的结果为准；不要提前标通过。
```
