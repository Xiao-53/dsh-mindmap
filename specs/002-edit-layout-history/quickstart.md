# Quickstart：实现后的人工验证指南

本文件是未来验证步骤，不是已执行结果。本轮没有构建、自动测试、浏览器或真机验收。完整行为见 [规范](spec.md)、[接口契约](contracts/editor.md) 和 [数据模型](data-model.md)。

## 前提与安装

- 由用户选定的后续实施完成；新图片/正文联合提交的内部失败保护取得单独验证证据后才开放实际写入。
- Node.js >=24.9.0，目标 DSH 为 0.2.2-rc.3，使用现有 profile 和工作区。使用独立验收地图，保留原有地图；不迁移或覆盖真实资料验证故障。
- 依赖未安装时在仓库根目录运行 `npm ci`；构建交付使用：

```powershell
npm run pack:plugin
```

按 [现有插件加载说明](../../docs/plugin-development.md) 加载新产物，实际文件名以届时 package.json 版本为准。本计划不指定版本，不执行安装或发布。构建成功不等于验收通过。

## 人工场景

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 详情自动保存 | 编辑标题/摘要/正文，停顿约 800ms，等已保存后重开 | 内容一致，节点身份、关系和手动位置不变 |
| 连续输入 | 保存期间继续输入，连续编辑中切换节点 | 最后输入未被旧回执覆盖；正常 flush 后直接切换，不弹确认 |
| 无效输入 | 清空标题，切图 | 草稿保留，提示标题无效；不写坏地图，允许修正、取消离开或明确放弃 |
| 图片 | 分别加入 PNG/JPEG/WebP，等保存后移走原文件，再重开和离线打开 HTML | 图片仍显示且比例正确；本机路径不出现在导出 |
| 图片共享 | 两节点引用同资源，只移除一处，再撤销/重做 | 另一处不受影响；撤销后可显示，不永久删资源 |
| 资源错误 | 用独立验收地图制造缺失图片，重新打开 | 其余正文可读，具体图片诊断可见，只读模式阻止写入；不伪造完整导出 |
| 模式 | 对 0、1、4、8、12 组图分别打开排列控件并切换可用模式，包括空组、无组节点和大小不均组 | 0/1 组只有纵向；4 组有纵向/田字型；8、12 组另有多列（均为 3 列）；卡片/组无自动排版遮挡，内容完整可达，组/边身份不变 |
| 模式失效 | 8 组图选多列后，让分组减少到 6 组（外部更新）再刷新 | 保留现有位置不自动重排，控件仍显示多列，可切换到其他模式或重置 |
| 保存与重置 | 在子图切模式、拖动、重开；单击重置再 Ctrl+Z | 模式位置保存；重置只改当前视图，一次撤销完整恢复 |
| 内容变化 | 已拖动布局下编辑长标题/正文，外部新增节点后刷新 | 旧坐标保留，新节点只补缺；不因内容保存整体重排 |
| 历史容量 | 31 次有效动作，混合详情批次、图片、拖动、模式和重置，再撤销/重做 30 次 | 只能回到第 1 步后状态，前后值一致；额外撤销无变化 |
| 重做分支 | 撤销两次后做新动作；另以缩放或导航作对照 | 新编辑清分支，阅读操作不清分支 |
| 快捷键焦点 | 分别在详情文字、画布、DSH 草稿和输入法组合状态按 Ctrl+Z/Y | 各自处理，不重复操作、不改宿主草稿 |
| 拖动取消 | 拖动后取消，随后正常拖动松手 | 取消完整恢复 manual 和位置且不计步；正常拖动一条历史 |
| 跨子图 | 子图 A 移动，再去 B 撤销 | 定位 A 并恢复，阅读历史不被当编辑历史 |
| 宿主直接关闭 | 持续输入未停顿直接关宿主侧栏，保持会话存活再打开 | 有效内容继续保存或可恢复；无效/失败草稿提示处理；旧历史不跨重开 |
| 外部冲突 | 在独立图存在本地修改时通过正常外部内容更新，再保存 | 提示冲突，保留副本，不静默覆盖；明确载入外部后清历史 |
| AI 修改后历史 | 做几步手动操作后，用 `/mindmap` 让 AI 修改当前图，等新版本载入后按 Ctrl+Z | 提示“导图已被外部更新，撤销记录已清空”；Ctrl+Z 不改动 AI 结果；随后手动操作重新计步；自动保存自身回执不触发清空 |
| 保存失败期间撤销 | 在独立验收图上让保存失败（如临时移除写权限），期间拖动、撤销、重做，再恢复权限并重试 | 撤销/重做照常生效且始终标记未保存；恢复后磁盘为最终状态，撤销回原状态时不产生写入；冲突时撤销暂停 |
| 旧文件 | 新插件打开 v1 布局，先阅读，再只改详情，最后改布局 | 前两步不改布局；实际布局修改才写 v2；未知版本拒绝而非重建 |

资源越界、结构破坏等属于拒绝场景，不通过只读降级绕过保护。浏览器/宿主进程退出和断电不属于会话草稿恢复保证。

## 量化记录

1. 12 组 120 节点，记录机器、侧栏尺寸、模式、从选择到可继续操作的时间；目标不超过 2 秒，手动记录，不在本轮增加自动性能采样。
2. 固定三张 8～12 组、至少 20 条跨组边地图；用相同内容、尺寸和统计规则记录 vertical/grid/columns 交叉数。共同端点不计；多段线每个不同相交点计一次。至少两张的最佳新模式比纵向减少 20%。未达到时记录失败，不换成“看起来更整齐”通过。
3. 每一步记录内容/坐标预期、实际状态与保存标记；30 次撤销重做全部一致才通过，不把“能按快捷键”代替容量验证。

## 内部验证（单独授权后）

不在本轮执行。沿用现有 `tests/integration/transaction.test.ts` 与 `atlas-tools-internal.test.ts` 基础，后续任务明确新增资源事务案例及精确运行命令；不直接运行 `npm test`，其 pretest 会构建 UI 测试模块。

必要覆盖：资源创建/正文写/回执各阶段失败；取消后回退；同 ID 同/不同摘要重试；响应丢失后回执复读；外部并发及跨 Host 认领；资源被外部修改后的回退拒绝；日志/请求体积上限；只读降级不可写；撤销后的版本条件；失败期间撤销后的净差异提交（含净差异为空不写入、部分目标成功）；响应丢失时先复读原 operationId 回执；面板关闭但会话存活的保存完成。记录通过/失败/未执行，新保护未验证前不开放实际多文件编辑。
