# DSH 正文位置引用与写入契约

以下为既有 v1 文字定位契约。空白行按 [正文选点设计](../insertion-followup.md) 使用 v2 的 `gap` 定位。

## 生成与加入草稿

1. 编辑正文时，右键菜单提供「添加图表/公式」。在菜单改变焦点前捕获实际点击的位置及对应段落。用正文源映射确认可插入的源码边界，保留段落和块内的既有结构。顶层文本段落使用段尾作为独立内容位置；能安全接受行内公式的列表、引文等位置可提供行内候选。独立插入若必须拆开现有结构才能放在该段后，则提示重新选择可用段落。空正文提供起始位置。图块自身菜单保留现有操作。
2. 目标需能对应已保存 Markdown。未保存编辑若使该段无法核对，提示保存后重新选点。是否加入引用不触发正文写入。位置快照显示地图、节点、点击处前后短文和所属段落，内容为空时标识「正文开头」。
3. 复用原生 `InputTriggerSource` 及 `captureInsertion`，绑定原会话与工作区。折叠 DSH 草稿选区到末端，使用捕获的 `draftRev` 调用 `insertReference`。现有文字、引用及附件保持原样。会话切换、草稿变化或宿主写入失败时，保留引用快照并按原会话重试规则处理。
4. 新引用 kind 为 `note-position`，包含有效版本的 `anchor`。点击草稿引用沿用来源导航，能精确定位时显示对应位置，否则保留可读快照及原因。发送序列化提供来源 ID、可读片段及可原样传回的定位数据，保留既有节点、选文和图块引用格式。会话 ID、工作区路径和资源地址留在客户端的宿主绑定。

## 定位载荷

| 字段 | 约束 |
| --- | --- |
| `version`、`kind` | 首版版本号为 `1`，`kind` 为 `block` 或 `start`。 |
| `mapId`、`nodeId`、`noteDigest` | 稳定 ID 与工具调用目标一致。摘要使用已有 SHA-256 工具对原始 Markdown 计算。 |
| `blockStart`、`blockLength`、`blockDigest`、`clickOffset` | 块定位的数据。偏移为安全的非负整数，`clickOffset` 相对块起点。源范围须落在可重新解析的完整块内。 |
| `previousBlockDigest`、`nextBlockDigest` | 块定位的相邻块摘要；边界可为 `null`。用于在正文变化后确认上下文和唯一性。 |

`start` 定位使用空正文的摘要，点击与块级插入位置均为源文开头。段落引用的可读快照只取有界片段，工具中的匹配由解析范围和摘要完成。

## 手动发送后的变更

1. 用户补充内容并手动发送。运行时 `/mindmap` 规则指引 DSH 以来源 `mapId` 与 `nodeId` 用 `atlas_read` 读取当前正文及 `fingerprint`，再按用户意图提供 `insert_note_content`。现有 `atlas_preview` 和 `atlas_apply` 接受该变更类型。
2. 定位插入请求只包含这一项变更。字段为 `op: insert_note_content`、`nodeId`、`anchor`、`kind`、`markdown`。一次接受一个 `inline_formula`、`display_formula` 或 `plot` 片段。继续使用 `expectedFingerprint` 和提交所需的 `operationId`，遵守现有工具大小限制。
3. 候选对当前 Markdown 重新解析。摘要匹配时验证原范围、锚点与安全边界。摘要不同时，只有段落、点击边界和邻近上下文足以唯一确认原位置时才解析出新范围。原段改写、重复候选或空节点已有内容时，提示重新选点并保留可读来源。
4. 行内公式拼接到该段的点击处，独立公式和图表放到该段之后。只在插入边界添加所需分隔；正文原有片段保持原样。重新解析候选并确认在预定位置仅新增预期的公式或有效顶层图块，避免误解码、吞并周围 Markdown 或重复图块 ID。首次写入空节点时检查笔记目标路径是否已被占用。
5. 使用现有授权、地图写入队列、实际版本检查和事务来提交候选。位置失效应返回可理解的错误并要求重新选点。地图在读取后再次变化时沿用版本冲突处理，重新读取并核对定位后才有新的提交候选。引用失效或校验失败时，skill 提示根据明确的新位置再执行，保留现有正文。
