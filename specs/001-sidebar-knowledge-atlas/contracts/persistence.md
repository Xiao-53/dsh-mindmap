# 插件保存与回退设计

## 责任与保证范围

主路径为：DSH调用插件地图工具 → 插件构造并校验变更 → 插件保存文件 → 发布提交完成通知 → 侧栏读取文件并渲染。界面编辑也进入同一服务。模型不执行文件删除、备份或回退，不通过通用文件工具绕过地图工具。

采用按地图串行执行、持久化恢复记录、文件前镜像和带版本条件的写入。它是插件负责的可恢复提交，不要求DSH提供跨文件事务原语，也不声称操作系统使整个目录瞬间替换。正常插件读者只看到提交前或提交后的有效快照；进程崩溃后先恢复，再开放地图。

外部编辑仍按既有规范支持刷新。外部编辑器不遵守插件队列，不能保证它看不到磁盘写入中间态；检测到外部改动时保留内容并报告冲突。此边界不阻塞常规工具保存设计。

## 记录与串行化

同一工作区、同一mapId的工具和界面写入共用队列。用本图 `.transactions/active.json` 的 createIfAbsent 认领活动操作，多个插件实例不能同时提交。记录 operationId、请求摘要指纹、相对文件清单、旧/新内容指纹、旧版本、前镜像/候选内容位置及状态；不含聊天、凭据或机器绝对路径。恢复资料位于 `.transactions/<operationId>/`，仅操作时建立，不作为地图内容或分享资源。

运行中锁不能被另一实例自动接管；进程重启的恢复须确认原操作已终止，不能凭超时删除锁。实现需明确单Host协调器生命周期，无法判断时标记恢复中并等待原所有者结束，而非并行回退。

## 保存步骤

1. 队列内读取当前结构及受影响笔记，检查expectedFingerprint，构造完整候选结构。验证ID、关联、父级、路径和笔记；删除先列出影响，沿用已有确认。生成布局补丁，不重置已有位置。
2. 建立活动记录，保存受影响文件的前镜像、候选内容及原本不存在的标记；确认可读且指纹一致后才标记prepared。准备失败时未修改任何正式文件。
3. 再次检查读集。按记录逐个使用条件写入/删除，并记录执行结果；新文件使用createIfAbsent。每个结果的版本用于后续恢复，不能用旧版本无条件覆盖。
4. 在同一队列中复读并校验最终文件；写入committed标记后发布一次mapChanged事件，再返回success及新指纹。写入期间侧栏保留原有效快照，文件观察事件延迟到操作结束处理。
5. 成功保留本次编辑撤销所需前镜像；结束编辑会话后只清理已完成且不再用于撤销的记录。失败或未完成记录不得自动清理。清理失败不撤销已成功的知识提交，单独报告维护状态。

## 失败、删除和恢复

- 普通写入失败：按逆序恢复已经生效的文件；更新文件恢复前镜像，新建文件删除，删除文件从前镜像重建。只在当前内容等于本操作写入结果时条件恢复。恢复完成返回failed_rolled_back，保留用户编辑供重试。
- 在写入和记录结果之间崩溃：启动时比较实际文件与记录的before/after指纹。等于before无需动作，等于after可恢复；既非before也非after视为外部冲突，不猜测和覆盖。
- prepared/applying且未committed：恢复前镜像后才能开放正常读取。committed：校验提交结果后开放，不能因通知丢失再执行一次相同修改。
- 回退也失败：保留恢复记录和最后有效快照，返回recovery_required，不返回普通“失败且已回退”。提供重试恢复或保留冲突副本的明确处理，不将半完成文件列为正常地图。
- 删除一律先保存前镜像，提交完成前可恢复。仅删除已列入影响清单且属于本图的文件，未知文件不删除；首次创建失败的目录也不能列为有效地图。
- 撤销是检查当前版本后执行的新操作；若后续内容已变，不把旧备份强行覆盖新版本。工具重试使用相同operationId和请求摘要，已提交则返回原结果，同ID不同请求拒绝。

## 实现验收门槛

实现阶段在每个写入、删除、标记更新及恢复边界注入失败，覆盖磁盘满、权限撤销、进程中断、重复请求及外部冲突。要求普通失败可完整回退；不可恢复时明确标记并保留恢复资料；不得报告虚假成功。这是写功能启用前的验证条件，不是技术规划必须等待宿主新API的阻塞。
