# Feature Specification: 多分组跨组卡片排版与连线路由深度优化

**Feature Branch**: `main`（沿用当前工作分支）  
**Created**: 2026-11-24  
**Status**: Draft  
**Input**: User description: "阅读 docs/research 调查文件，准备实施多分组跨组卡片排版与连线路由深度优化"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 真实卡片高度与多分组跨组全局联合排版 (Priority: P1)

用户在创建或重置包含多个分组、不同卡片高度或强跨组耦合关系的思维导图时，系统在布局阶段直接使用每张卡片的实际渲染高度与最终连线完全一致的几何判定，把整张视图内的所有非空分组作为一个整体联合求解。无论是纵向排列的多分组跨段跳跃连接，还是田字型双列排列中左右与上下分组并存的强耦合连接，系统都能自动协同各分组内部的节点列位：在纵向视图中对齐跨组上下游列位、大幅消除斜穿多卡，在田字型视图中同时兼顾左右相邻分组的水平行对齐与朝向内侧边界贴靠。同时，所有分组继续保持规整的三列离散对齐、首行紧凑无空洞、独立分叉或菱形层次清晰、纯孤立分组按原序平铺，以及视图原有的分组叙事先后顺序。

**Why this priority**: 先前版本布局阶段按固定行高和简化网格预测连线，且仅逐组局部扫描排布，导致卡片变高时纵向穿卡误判、多分组复杂视图陷入局部交叉死锁以及田字型双列横纵解耦。只有从布局与路由同源评估出发开展全视图联合排版，才能在源头上大幅压低跨卡穿刺、真实曲线交叉与跨组冗余线长。

**Independent Test**: 构造涵盖“短行到多行长摘要混排的极端变高卡片”、“四个纵向分组跨段跳跃连线”、“2×2 田字型强耦合四分组”及既有回归结构（严格三列、独立一分三/菱形、长链蛇形折行）的测试导图，执行初始生成与切换排列/重置排列：核查实测高度不同的卡片之间无高度错位造成的穿卡漏判，田字型左右组相连卡片向内侧边界贴靠且行高就近对齐，整体非端点卡片穿刺数、曲线交叉数与跨组线长较旧版显著下降，所有卡片零重叠且既有回归特征保持不变。

**Acceptance Scenarios**:

1. **Given** 视图中同一行或上下相邻行混排了简短标题卡片与包含长摘要的高卡片，**When** 系统执行初始排版或重置排列，**Then** 系统依据每张卡片的实际测量高度累计行坐标并判定连线穿卡风险，高矮变化不会造成跨卡穿刺漏判或上下卡片遮挡，且继续保持三列离散对齐与首行紧凑填满。
2. **Given** 视图切换为田字型双列排列且左右相邻分组或上下相邻分组之间存在多条跨组连线，**When** 系统联合排布各分组节点，**Then** 左右相邻分组中的相连卡片自动向彼此相向的内侧边列贴靠并对齐行高，上下相邻分组中的相连卡片对齐同列位置，大幅减少对角斜穿与穿卡现象。
3. **Given** 视图包含多个纵向排列分组且存在跨多组跳跃连线或协同对称交叉，**When** 系统执行全局联合排版，**Then** 系统能够跨越单组局部限制协同调整相邻分组的列序，在不颠倒视图原有分组叙事顺序的前提下解开交叉死锁并缩短跨组连线总长。
4. **Given** 分组内没有任何组内和跨组连线，或属于无跨组边的独立分叉/汇合/菱形结构，**When** 系统计算排列位置，**Then** 孤立分组仍按原始输入顺序规整平铺，独立分叉与菱形结构继续保持对称分层居中，既有核心版面秩序完全保留。

### User Story 2 - 组内循环与跨组长回路的结构化排布与外侧通道引导 (Priority: P1)

当思维导图包含概念互推（双向互连）、组内多节点循环依赖，或从下游分组返回上游分组的长距离反馈连线时，系统不再按机械顺序乱断环路或对合理回边施加错误的倒拉惩罚。对于组内循环与双向边，系统优先保留主要依赖关系和原本叙事顺序下的主干骨架，使同属一个循环的概念聚拢在相邻区域，同时不把末端节点强行倒拉回首行；对于逆向返回上游分组的跨组回边以及跨越两个及以上分组的长距连线，系统主动将其两端节点牵引至视图最外侧边界列，让长回边沿画布外缘干净绕行，避免横切穿过中间分组的卡片。

**Why this priority**: 知识图谱与流程导图中极易出现双向关系与反馈闭环。旧版简单破环既容易拆散主干流程，又把跨组回边留在中间列直穿多张卡片，严重破坏跨分组主脉络的可读性。

**Independent Test**: 构造包含“同对节点双向互连”、“组内 3～4 节点循环闭环”以及“跨 2～3 个分组的下游到上游反馈连线”的导图视图，执行初始排版与重置排列：核查主干依赖流向清晰连贯、循环概念彼此紧邻、合理回边不破坏首行到末行主干序，且跨组反馈连线与跨多组长距边优先对齐到视图左右外边界列以减少对中间分组卡片的穿刺。

**Acceptance Scenarios**:

1. **Given** 分组内部存在两节点双向互连或多节点闭环依赖（同时混合主要依赖与补充关联），**When** 系统计算组内节点拓扑与落位，**Then** 系统优先保留主要依赖边和原有叙事主干顺序，将成环节点聚拢排布，且不对已识别出的组内合理回边施加逆流惩罚。
2. **Given** 视图中存在从下游分组指向上游分组的跨组回边，或纵向跨越两个及以上分组的远距连线，**When** 系统执行全视图联合排版，**Then** 系统优先将此类连线的起止卡片安置在视图左右最外侧边界列，引导其转为干净的外侧拱桥绕行，显著减少横切中间分组卡片正面的现象。

### User Story 3 - 双向与平行斜线清晰分离、外侧拱桥护栏分层及高亮光晕补强 (Priority: P1)

在画布渲染连线时，面对面双向斜向连线不再在中段纠缠形成“双交叉”，同向多条平行斜线也不会在窄缝里粘连挤压。对于同排或同列隔卡直连，系统在释放阶梯状分组外侧合法拱桥空间的同时，严格保护分组标题栏与画布左边缘不被拱桥越界切穿；当同侧存在多条相互重叠或共端点的外侧拱桥时，拱桥按跨度从内向外整齐彩虹分层且长短拱桥出口互不交叉。用户单击选中某张节点卡片以查看原本穿底的关联连线时，提层到卡片上方的连线底层呈现柔和的画布背景色光晕，隔开卡片文字干扰、确保高亮脉络清晰可辨。

**Why this priority**: 卡片位置排优之后，若渲染阶段仍存在双向斜线双交叉、平行线粘连、同端多拱桥打架、顶拱切穿分组标题或高亮线混入卡片正文，画布在多关系并发场景下依旧显得杂乱难读，且必须在保持拖拽零延迟跟手和单段柔和曲线的前提下完成精修。

**Independent Test**: 在包含“标准列距错位面对面双向斜线”、“同向多条平行斜线”、“上宽下窄阶梯分组外侧拱桥”、“首行三卡隔卡顶拱”、“同端点多条嵌套外侧拱桥”及“单击选中穿底连线节点”的测试场景中逐项核查：双向与平行斜线实现零交叉且保持清晰分离净空，慢速拖过双向/拱桥临界线不闪烁，顶拱始终落在标题底边与卡片顶边之间，嵌套多拱桥外高内低且出口零交叉，高亮提层连线在浅深双主题下带清晰底层光晕，且 40 节点 / 60+ 边连续拖拽全程跟手流畅。

**Acceptance Scenarios**:

1. **Given** 两张斜向错位相邻卡片之间存在面对面双向连线，或存在两条及以上同向面对面平行斜线，**When** 画布生成端口槽位与曲线路径，**Then** 双向连线依据两端相对斜向方位智能配对槽位、完全消除中段双交叉（拖拽跨过临界线时通过滞回缓冲防闪跳），平行斜线在保持垂直端口衔接下对称展开中段曲线、维持清晰可见的分离净空。
2. **Given** 上方分组较宽而下方分组较窄呈阶梯状排列，且下方窄分组外侧存在同排或同列隔卡直连，**When** 系统判定是否启用外侧拱桥，**Then** 仅检测与当前拱桥跨度范围重叠的其他卡片，不因远处宽分组误杀下方合法外侧拱桥，同时内部列或内部行的隔卡连线仍维持穿底直连。
3. **Given** 首行或最左侧列存在被激活的外侧隔卡拱桥，或同一外侧方向并发多条区间重叠、共享同一端点的外侧拱桥，**When** 画布计算拱桥曲线与端口顺序，**Then** 水平隔卡拱桥优先绕行下侧空旷空间；若必须走分组上方，拱顶严格保持在分组标题栏底边之下与卡片顶边之上（左侧拱桥亦不越出画布左边缘）；多条重叠拱桥按跨度由短到长从内向外彩虹分层，共享同一端点时“长拱桥占外侧端口、短拱桥占内侧端口”，实现零交叉分层跨过。
4. **Given** 用户在浅色或深色主题下单击选中某张拥有穿底连线的卡片，**When** 直接关联的连线与关系胶囊提层至卡片上方高亮显示（鼠标仅悬停时不触发提层），**Then** 高亮连线底层自动呈现柔和的画布同色背景光晕以区隔卡片正文，且在包含 40 个节点与 60 条以上连线的视图中拖动任意卡片保持跟手零延迟。

### User Story 4 - 四维防遮盖的关系胶囊与极短边自适应定位 (Priority: P2)

在多条连线交叉且带有中文关系名称的复杂视图中，关系胶囊标签在沿曲线寻找停靠位置时，不仅躲避节点卡片和已放置的其他胶囊，还主动避开其他连线路径以及所有端口圆点与箭头，避免胶囊压住旁边连线的箭头或拐角。当连线两端卡片在水平或垂直方向紧邻、间距极窄时，水平短边胶囊稳妥居中并自动按净空收窄宽度，竖向极短边胶囊则灵巧停靠在行间窄缝走廊的连线外侧旁侧，既不遮住卡片边框与箭头，又保持清晰归属感。

**Why this priority**: 旧版胶囊仅躲避卡片和已放胶囊，在交叉多线和短间距连线场景中仍频繁压住相邻连线的箭头或盖住卡片边框与箭头；消除胶囊四维遮盖能显著提升高密度标注导图的文字可读性。

**Independent Test**: 构造同时包含交叉斜线标注、标准水平短间距标注和标准竖向行间短间距标注的多组测试场景，检验浅色与深色主题渲染结果：核查胶囊与卡片、他胶囊、他线路径及所有端口/箭头的碰撞次数，检验水平短边胶囊是否居中且不压两端卡片边框与箭头，检验竖向极短边胶囊是否平稳侧鞍停靠于行间走廊侧边，并验证超长文字省略截断及悬停显示全文。

**Acceptance Scenarios**:

1. **Given** 视图中多条带有名称的关系连线彼此交叉或邻近其他连线的端口圆点与箭头，**When** 系统为各条连线放置关系胶囊标签，**Then** 系统严格按“不压任何卡片 > 最小化与已放胶囊、端口/箭头及其他连线路径的冲突 > 尽量贴近曲线中点”的优先级自动择优停靠。
2. **Given** 两张同排紧邻卡片之间存在带有中文名称的短水平连线，**When** 系统放置关系胶囊标签，**Then** 胶囊以两张卡片边框之间的真实净空中点为首选停靠位，并根据实际净空自适应收窄最大允许宽度，使常规短名称完整安放在净空内且不触碰两端卡片边框与箭头（过长文字仍以省略号收束并在悬停时显示完整内容）。
3. **Given** 两张同列上下紧邻卡片之间存在带有名称的极短竖向连线，**When** 行间竖向间隙过窄难以居中放置胶囊，**Then** 胶囊自动优先悬停在连线右侧（其次左侧）的行间走廊侧鞍位置，不压盖上下卡片边框、输出圆点或输入箭头，且视觉上明确紧贴所属连线。

### User Story 5 - 框内优先增量补位与保留手动位置的局部整理 (Priority: P2)

当用户已经手动拖放调整过部分节点（包括把某些卡片拖出了原分组外框），之后通过补充内容向同一分组新增了与该脱框邻居相连的节点时，新节点不会跟着落到分组框外的荒野区域，而是优先落回所属分组外框内部最靠近该邻居的空闲位置，同时原封不动保留所有既有卡片与分组框位置。此外，用户可在画布顶部工具栏一键执行“整理未锁定节点”，在不触动任何已手动微调位置卡片与既有分组框的前提下，自动整理其余未锁定节点消除杂乱；系统还具备单分组局部整理能力，只重排单个指定分组内部卡片而保持视图其余全部分组零位移。

**Why this priority**: 解决旧版“自由拖放与后续自动补位冲突”及“想整理局部杂乱就必须牺牲全图所有手动精调位置”的两难困境，让人工精调与自动排版平滑共存。

**Independent Test**: 第一项测试：将某已保存视图中的某张节点拖出所属分组外框，随后在同分组内新增一个与之相连的未定位节点，验证新节点精准落入原分组外框内最靠近该邻居的空闲标准位且既有节点和分组框零漂移；第二项测试：在部分卡片已手动锁定并可能偏离标准网格的视图中，点击顶部工具栏“整理未锁定节点”，验证锁定节点和分组框位移为 0、未锁定节点重新整齐排布且全图零重叠，并验证一步撤销可完整恢复整理前状态；同时验证按单分组范围触发局部整理时其余分组与卡片位移为 0。

**Acceptance Scenarios**:

1. **Given** 视图已有保存的布局，且某张节点已被用户手动拖离所属分组外框，此时同分组内新增了一个与该脱框节点相连的未定位节点，**When** 系统计算新增节点的增量补位坐标，**Then** 系统优先枚举原所属分组框内所有未被占用的标准空位，把新节点安置在框内距离该脱框邻居最近的无重叠空位上（仅当框内已无可用空位时才安全外推），所有既有节点与分组外框坐标保持不变。
2. **Given** 视图中同时存在用户已手动拖放锁定的节点和未手动锁定的节点，**When** 用户在画布顶部工具栏点击重置按钮旁的“整理未锁定节点”动作，**Then** 全部已手动锁定节点与所有既有分组外框保持零位移，系统仅基于实际卡片高度重新优化排布未锁定节点并严格避开锁定卡片，确保整理后无任何卡片重叠，且结果即时接入自动保存与撤销/重做历史。
3. **Given** 需要对某个指定分组单独执行局部整理，**When** 系统按单分组范围执行局部重排，**Then** 其余所有分组与成员节点保持零位移，目标分组内部节点按实高协同原则重排且严格不与他组或锁定卡片重叠，并可根据需要保持目标分组原外框或紧凑重算该组外框。
4. **Given** 用户打开工作区中历史已保存布局的导图，或将其导出为独立离线阅读页，**When** 对比查看宿主桌面原生侧栏（浅色/深色主题）与独立离线阅读页，**Then** 既有已保存坐标 100% 零静默漂移；除离线只读页不提供编辑整理入口外，双端在卡片排布、分离曲线、分层拱桥、高亮光晕与胶囊停靠上保持完全一致。

### Edge Cases

- **卡片高度极端差异**：当同一排或相邻排同时存在极矮单行卡片与包含多行长摘要的高卡片时，所有行高累加、穿卡检测、同向/双向斜线路由与胶囊避让均按实测高度运行，不得出现上下卡片压盖或穿卡漏判。
- **高密度环路与跨组回边并发**：当一个视图内同时存在多个节点组成的多节点循环闭环、双向互连以及跨多分组逆向回边时，计算必须在固定有限步骤内以 100% 确定性收敛，不出现无限循环或每次打开位置跳变。
- **阶梯状多分组宽度与边缘拱桥冲突**：当田字型双列中右列分组存在左外侧拱桥、或纵向首行分组存在顶外侧拱桥时，拱桥护栏必须确保拱弧既不侵入所属分组标题栏、不越出画布左侧边界，也不侵入双列布局下相邻列分组的标题区域。
- **慢速拖拽跨越临界区**：用户按住卡片在双向斜线上下翻转临界线或同排/同列隔卡拱桥临界线附近来回慢速微移时，通过进入与退出滞回机制抑制高频闪变，单次缓慢越界切换次数不超过 1 次。
- **极短连线配较长关系标签**：在水平或垂直紧邻极短边上存在较长中文关系名称时，水平边胶囊收窄宽度居中省略、竖向边胶囊侧鞍悬停走廊且不遮挡箭头；任何情况下胶囊不得飞离所属连线，鼠标悬停可完整阅读原文。
- **同侧多条嵌套拱桥并发**：同一张卡片同一侧边缘向外发出两条及以上不同跨度的外侧拱桥时，端口排列与拱桥高度必须严格联动（长拱桥外端口配高拱道、短拱桥内端口配低拱道），消除出口交叉与中段粘连。
- **局部整理边界条件**：当视图中所有节点均已被手动锁定、或手动锁定节点彼此紧贴且不在标准网格位置时，触发“整理未锁定节点”不得移动任何锁定节点、不得改动既有分组框，且新排布的未锁定节点仍必须严格保持零重叠（全锁定时安全保持原样）；当邻居被拖出框外且原分组框内标准空位已占满时，补位回退至邻居周边最近的无重叠空位。
- **大规模压力视图流畅度**：当单视图包含 40 个节点与 60 条以上连线时，全视图排列计算必须在用户无感知的短时间内完成，连续拖拽任意卡片 30 秒保持流畅跟手、无页面卡顿或崩溃。

### Key Entities

- **全视图实高协同排版模型（View-Wide Real-Height Layout Model）**: 以每张卡片实测高度和同源连线几何评估评价整张视图全部非空分组的离散三列联合布局模型，在纵横两个布局模式下协同跨组距离、实高穿卡与曲线交叉。
- **回路拆解与外侧回边通道（Cycle Resolution & Outer Feedback Channel）**: 对双向互连、组内多节点循环及跨组长逆向反馈边进行结构化识别与空间引导的规则集合，兼顾组内循环聚拢、主干序保全与外边界通道避卡。
- **分离式曲线与彩虹分层拱桥（Separated Curves & Layered Outer Arches）**: 结合斜率感知双向槽位配对、平行斜线反向展开、跨度感知外卡检测、标题/画布护栏钳位、彩虹轨道分层与长外短内嵌套端口序的轻量局部连线几何集合。
- **四维避让关系胶囊（Four-Way Obstacle-Aware Edge Pill）**: 综合避开节点卡片、已放置胶囊、其他连线路径及端口/箭头的自适应标签停靠单元，涵盖水平短边净空收窄与竖向极短边侧鞍走廊停靠规则。
- **保留锁定节点的局部整理（Locked-Preserving Partial Relayout）**: 在钉死全部已手动锁定节点与既有分组外框（或指定他组）零漂移的前提下，仅重排未锁定节点或目标分组并接入撤销栈的局部重排机制。

## Assumptions

- **默认沿用严格三列离散网格对齐**：基于对“严格三列离散网格”与“半步连续水平重心微调”的定量对比结论，连续半步微调虽在纯对称 3 连 2 汇合中略微缩短线长，但会令常见 1 对 1 跨组垂直连线失去笔直直线并明显增加总长，因此本特性默认延续严格三列离散网格，暂不自动启用连续半步坐标偏移。
- **默认保留原有分组叙事顺序**：纵向排列严格按照导图定义的分组数组顺序自上而下排布，田字型排列默认沿用双列叙事次序，通过跨组协同与耦合换列化解连线交叉，不私自打乱章节分组前后次序而破坏用户的知识心智地图。
- **默认优先外侧避卡通道而非中列穿底**：在强回路与多组跳跃场景下，将跨组回边与长距跨多组边牵引至外侧边界列转为外侧拱桥，能够大幅消除非端点卡片正面穿刺，尽管会以可控小幅弧长增长换取全局脉络无遮挡，本特性采用该策略作为默认权重取向。
- **局部整理入口保持轻量化**：界面层默认仅在画布顶部工具栏重置按钮旁新增“整理未锁定节点”按钮，保持画布分组背景容器纯视觉展示不引入额外鼠标噪点；底层单分组局部整理能力同步完备，可供后续工具或特定操作按需调用；离线导出页面定位为纯阅读视图，不提供任何局部整理编辑按钮。
- **遵守项目宪章与职责边界**：AI 内容生成仍只产出知识结构与 Markdown 正文，不涉及界面布局或坐标计算；不修改 `map.json` 与 `layout.json` 持久化格式，不引入重型第三方图布局框架；本阶段仅完成功能规范编写与检查，不擅自推进至澄清、技术规划或编码实现阶段。
