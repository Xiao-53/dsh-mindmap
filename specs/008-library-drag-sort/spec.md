# Feature Specification: 思维导图管理页拖放定位与手动排序

**Feature Branch**: `main`（沿用当前工作分支）
**Created**: 2026-11-18
**Status**: Draft
**Input**: User description: "思维导图管理页面有问题，拖动文件从文件夹中进出可能导致识别进入回收站。同时没法手动对思维导图排序，只能使用默认排序。我希望可以直接拖动到某一个导图下直接放下去"

## Clarifications

### Session 2026-11-18

- Q: 既然重启 DSH 后未再复现误入回收站的问题，本轮规范是否仍保留“拖拽期间严格隔离回收站”的防御性要求? → A: 不管之前回收站的问题了，仅聚焦优化现有的拖放移动与手动排序逻辑。
- Q: 这次手动排序是只针对思维导图本身，还是文件夹也需要支持手动调整顺序? → A: 思维导图和文件夹各自支持手动排序（同级内所有文件夹仍整体排在导图上方），且不允许文件夹嵌套文件夹。
- Q: 拖放交互与搜索筛选期间应如何表现? → A: 采用单鼠标直观拖放并在目标行上方或下方显示横线插入指示（如图示效果）；搜索筛选期间禁用拖放排序与移动，保持交互简单且不破坏隐藏项目的顺序。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 直接拖放导图与文件夹完成归位及手动排序 (Priority: P1)

用户在思维导图管理页面整理内容时，可以用鼠标直接按住一张导图，拖到任意目标导图下方（无论目标导图位于根目录还是某个文件夹内），目标位置出现清晰的横线插入指示后直接松手放下，系统立即将其移动到目标导图所在层级并排在目标导图正下方；也可以拖到第一张导图上方将其排到第一位，或拖入空文件夹、折叠文件夹行及根目录区域完成归类移动。同时，用户可以拖动文件夹调整文件夹之间的排列顺序；文件夹始终为单层结构，不能把文件夹套进另一个文件夹中，且所有文件夹整体排在根目录导图上方。

**Why this priority**: 这是用户最核心的诉求——同时解决“把导图放到哪里（包括顺畅地从文件夹移出或移入）”“导图和文件夹各自排在谁前后（手动排序）”以及“避免拖动文件夹时意外套娃或从文件夹内拖放导图意外弹回根目录”。

**Independent Test**: 在包含根目录导图、多个单层文件夹及文件夹内导图的管理页面中，分别执行“同级导图上下重排”“将文件夹内导图拖到根目录某张导图下方”“将根目录导图拖到已展开文件夹内某张导图下方”“拖动文件夹调整文件夹前后顺序”，验证每次松手前都有清晰的横线插入指示或目标高亮，松手后立即出现在预期位置且不会发生文件夹嵌套。

**Acceptance Scenarios**:

1. **Given** 根目录或同一文件夹内已有导图 A、B、C，**When** 用户拖动导图 C 到导图 A 下方并松手，**Then** 导图 A 下方显示横向插入指示线，松手后顺序立即变为 A、C、B。
2. **Given** 导图 X 位于文件夹 F1 内，根目录存在导图 A、B，**When** 用户将导图 X 从 F1 拖到根目录导图 A 下方并松手，**Then** 导图 X 移出 F1 进入根目录，并排在导图 A 与 B 之间。
3. **Given** 导图 A 位于根目录，文件夹 F1 已展开且内部有导图 M1、M2，**When** 用户将导图 A 拖到 M1 下方并松手，**Then** M1 与 M2 之间显示横向插入指示线，松手后导图 A 移入 F1 并排在 M1 与 M2 之间（不会因事件冒泡误移到根目录）。
4. **Given** 用户需要将导图 B 调整到当前列表最顶部，**When** 用户将导图 B 拖到当前层级第一张导图 A 的上方并松手，**Then** 导图 A 上方显示横向插入指示线，松手后导图 B 排在导图 A 之前。
5. **Given** 文件夹 F2 为空或处于折叠状态，**When** 用户将导图 A 拖到 F2 行上（或空文件夹提示区）并松手，**Then** F2 高亮为移入目标，松手后导图 A 移入 F2 并显示在该文件夹内。
6. **Given** 存在文件夹 F1、F2、F3 与根目录导图 A，**When** 用户将文件夹 F3 拖到文件夹 F1 上方或下方并松手，**Then** F1 上方或下方显示横向插入指示线，F3 不会嵌套进 F1 中，而是调整到 F1 之前或之后，且所有文件夹仍整体排在根目录导图 A 上方。

### User Story 2 - 手动排序持久保留并兼容多选、新增与恢复 (Priority: P2)

用户手动排好的文件夹顺序和导图顺序能够自动保存，在打开导图后返回管理页、刷新列表或重新打开工作区时保持不变；同时在多选拖动、新建文件夹或导图、从回收站还原或删除文件夹等常规操作下，已有手动顺序不被意外打乱。

**Why this priority**: 如果手动排序只在当前画面有效而无法保留，或在新增、还原导图后全部重置，用户将不得不重复整理，大幅降低管理页面可用性。

**Independent Test**: 手动调整文件夹顺序以及根目录和文件夹内导图顺序后，分别执行“打开导图再返回”“刷新页面”“新建文件夹和导图”“删除再还原一张导图”，检查原有项目的相对顺序始终保持一致。

**Acceptance Scenarios**:

1. **Given** 用户已手动排好文件夹顺序以及根目录与某文件夹内的导图顺序，**When** 打开任意导图后返回管理页面，或重新载入工作区，**Then** 文件夹及各层级导图仍按用户手动排列的顺序显示。
2. **Given** 用户已通过多选选中导图 B 和 C，**When** 将所选项目拖到导图 A 下方并松手，**Then** B 和 C 按其原有相对顺序一起移动到目标位置且排在 A 下方；所选目标本身属于本次拖动集合时，不产生错乱或自引用错误。
3. **Given** 已有手动排好顺序的文件夹和导图列表，**When** 用户新建文件夹、新创建或外部新增一张导图，**Then** 新项目追加到所在区域末尾，原有文件夹与导图的相对先后顺序保持不变。
4. **Given** 用户从回收站还原一张导图，**When** 还原完成返回管理页面，**Then** 该导图恢复到有效列表（原所属文件夹仍存在时回到该文件夹末尾，否则回到根目录末尾），不打乱其余导图的手动顺序。

---

### Edge Cases

- **拖到自身或相邻原位**: 将导图或文件夹拖到自身上方、自身下方或紧邻前一项下方导致实际归属与顺序均未变化时，不触发多余保存或报错，原有状态保持不变。
- **在无效区域释放或取消拖动**: 拖动过程中在非可落放区域松手或按下取消键（如 Esc）时，本次拖动取消，所有导图与文件夹的归属和顺序保持原样。
- **拖动文件夹经过导图区或空白区**: 拖动文件夹时，不能将文件夹拖入另一文件夹内部，也不能插入到两张导图之间混排；拖向导图区或无效落点时不显示插入线并在松手后保持原位，始终维持“文件夹区在上、导图区在下”。
- **根目录尚无导图时移出文件夹**: 根目录仅有文件夹、没有根级导图时，将文件夹内导图拖到根目录标题区或根目录导图区仍能顺利移出到根目录。
- **多选混选拖动**: 在开启「选择」同时选中文件夹与导图并拖动时，仅按合法目标类型处理（拖向导图位置时只移动所选导图到目标位置，拖向文件夹排序位置时只重排所选文件夹），不破坏“文件夹不嵌套、不与导图混排”的规则。
- **搜索筛选状态**: 当用户在搜索框输入关键词筛选导图和文件夹时，禁用拖放排序与移动，避免局部视图误改未显示项目的相对顺序。
- **窄侧栏连续列表与滚动**: 在较窄的侧栏宽度下，相邻导图行、折叠文件夹行及空文件夹提示区之间的落点判定彼此清晰不重叠，用户用单鼠标即可稳定命中“某导图下方”或“某文件夹上下方”。
- **保存失败保护**: 当移动或排序保存失败时，界面给出明确错误提示，不误报成功，也不丢弃原有有效顺序。
- **回收站视图内**: 在回收站页面浏览待还原或待永久删除的导图时，不提供拖动移动或排序操作。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 管理页面 MUST 支持用鼠标将导图直接拖动到任意目标导图下方（以及首项或任意目标导图上方）并松手落位，同时完成所属文件夹（或根目录）变更与手动位置更新。
- **FR-002**: 管理页面 MUST 支持拖动文件夹直接调整文件夹之间的排列顺序；同时 MUST 禁止文件夹嵌套进另一个文件夹，也不允许文件夹与导图混合穿插排序，所有文件夹始终整体排在根目录导图上方。
- **FR-003**: 管理页面 MUST 在拖动悬停过程中提供清晰、实时的视觉落点指示：在插入排序位置（导图上方/下方或文件夹上方/下方）显示一条横向插入指示线，在移入折叠/空文件夹或空根目录区域时高亮对应容器，避免用户在松手前无法判断落点。
- **FR-004**: 拖动导图经过或落入已展开文件夹内部区域及其中导图行时，系统 MUST 准确识别为目标文件夹及对应位置，不得因事件向上冒泡而错误归属到根目录；在无效区域释放或取消拖动时，项目保持原有归属与顺序。
- **FR-005**: 管理页面 MUST 分别为根目录文件夹列表、根目录导图列表以及每个文件夹内部的导图列表维护独立的手动排序，取代单一默认排序；未设置过手动顺序的项目保留可预期的默认顺序。
- **FR-006**: 文件夹和导图的手动排序结果 MUST 在移动或排序操作完成后自动保存，并在切出查看导图再返回、刷新列表以及重新打开工作区后持续保留。
- **FR-007**: 支持将导图拖入已展开或折叠的文件夹行、空文件夹区域，以及在根目录无其他导图时拖到根目录区域完成移出；拖入折叠或空文件夹时，该导图落在目标文件夹内的末尾位置。
- **FR-008**: 多选模式下拖动多个导图到指定导图下方时，系统 MUST 将所有合法的被拖动导图按原有相对顺序整体插入目标导图之后，并忽略会导致自身引用自身或跨类型混排的无效落点。
- **FR-009**: 新建文件夹、新增导图或从回收站还原导图时，新加入或还原的项目追加到目标区域末尾；重命名或删除文件夹（其内容移回根目录末尾）时，系统 MUST 保留未受影响文件夹与导图的既有手动先后顺序，不得将列表重置回默认排序。
- **FR-010**: 当搜索筛选处于激活状态或用户位于回收站视图时，系统 MUST 禁用拖放移动与重排操作，保护未展示项目的已有顺序。
- **FR-011**: 当拖放归属或排序保存失败时，系统 MUST 给出明确提示且不错误显示保存成功，保证页面状态与持久化数据一致。

### Key Entities

- **导图条目（Mindmap Entry）**: 管理页面中可打开、可归类到单层文件夹或根目录、可手动排序的学习导图，具有独立于标题的稳定身份。
- **文件夹（Folder）**: 用于单层分组管理导图的容器，支持折叠与手动排序，不允许嵌套子文件夹；所有文件夹整体展示在根目录导图之前。
- **手动排序序列（Manual Order）**: 根目录文件夹序列、根目录导图序列及各个文件夹内部导图序列，用于确定各自展示先后，并与默认顺序、新增及还原项兼容。
- **拖放落点目标（Drop Target）**: 拖动过程中根据指针位置与被拖动对象类型识别出的语义化落点，包括“某导图上方/下方”“某文件夹上方/下方”“目标文件夹内部”及“根目录”。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户在测试导图库中用鼠标执行 12 次连续拖放操作（涵盖同级导图重排、从文件夹拖出到根目录指定导图下方、从根目录拖入已展开文件夹内指定导图下方、拖到首项上方，以及文件夹上下重排），12 次均在松手前看到明确的横向插入指示线或容器高亮，并一步直达目标归属与顺序位置，且全程不会发生文件夹嵌套。
- **SC-002**: 手动调整文件夹顺序以及根目录和文件夹内共 6 张以上导图的顺序后，执行页面刷新、打开导图再返回以及重新打开工作区，100% 的文件夹与导图顺序均与调整结果完全一致。
- **SC-003**: 在已有手动排序后，依次执行“新建 1 个文件夹与 1 张导图”“将 1 张导图删除至回收站后再还原”“删除 1 个非空文件夹”，原有其余文件夹与导图的相对顺序保持 100% 不变。

## Assumptions

- 此前出现的回收站误识别现象在用户重启 DSH 后未再复现，用户已确认本轮不再针对该历史回收站问题单独处理，仅聚焦优化现有的拖放移动与手动排序逻辑。
- 文件夹采用单层结构（不允许文件夹套文件夹）；文件夹与导图各自支持手动排序，同一页面中所有文件夹整体位于根目录导图上方。
- 管理页面中的「直接拖动到某一个导图下直接放下去」指通过鼠标直接拖动并在目标导图下方（或上方）显示横向插入指示线，松手后将导图插入该位置并自动归入同一文件夹（或根目录）。
- 默认排序仍作为尚未手动排序时的初始兜底顺序；一旦用户通过拖动调整过某层级顺序，该层级即按手动顺序展示，新增或还原的项目追加到对应区域末尾。
- 搜索过滤或回收站视图下禁用拖放排序与移动，保持单鼠标操作简单可靠，同时保护未展示项目的已有顺序。
