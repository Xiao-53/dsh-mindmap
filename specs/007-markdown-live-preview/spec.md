# Feature Specification: 节点正文 Markdown 实时预览编辑

**Feature Branch** `main`\
**Created** 2026-11-18\
**Status** Draft\
**Input** 调研 Obsidian 的 Markdown 编辑器，借鉴 Live Preview 改善 DSH 导图节点正文的手动编辑。

本规范补充[节点详情阅读与编辑样式统一](../005-unify-note-presentation/spec.md)，更新[公式预览](../003-latex-formula-preview/spec.md)中单条公式的编辑和确认流程。用户在节点详情内直接编辑，光标附近的 Markdown 标记可以显露，其他内容继续按阅读样式显示。现状与官方资料见[调研记录](research.md)。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 在阅读排版里连续编辑正文 (Priority: P1)

用户在节点详情底部「复制内容」旁点击「编辑」，接着在原来的位置改段落、标题或列表。光标进入加粗、斜体等格式时，可以直接调整标记。移开光标后，所在内容恢复排版。

**Why this priority**　用户每天都会编辑正文。普通键盘输入应保持连续，避免光标跳走、列表错位或编辑提示挡住下一步。

**Independent Test**　打开包含三级标题、嵌套有序和无序列表、加粗与斜体的长笔记。在正文中段切换模式，依次编辑、回车、退格、粘贴，并用中文输入法完成一段文字。

**Acceptance Scenarios**

1. **Given** 用户滚动到含标题和列表的中段，**When** 点击「编辑」再点击「完成」且没有改动正文，**Then** 原段落仍在视野内，标题层级、字号、颜色和缩进一致。
2. **Given** 文中含 `# 一级标题`、`## 二级标题`、`### 三级标题`、`**加粗**`、`*斜体*` 和 `***组合***`，**When** 光标依次移入对应内容再离开，**Then** 进入时可以选中、增删标记，标题和文字格式仍可辨认。离开后隐藏已成对的标记，仅显示同一份排版内容。
3. **Given** 用户编辑有序或无序列表，**When** 在有文字的条目末尾按 Enter，**Then** 在同一缩进层级续写一个条目。**When** 对空条目按 Enter 或在其内容起点按 Backspace，**Then** 顶层退出列表，嵌套层退出当前层，空标记随之消失，未操作的列表文字保留。
4. **Given** 光标在列表、标题或普通段落，**When** 用户选中原有内容后输入中文、粘贴多行或删除选区，**Then** 变更作用于实际选区，中文组合结束后仅提交最终文字，光标留在实际编辑结果处。

### User Story 2 - 连续编辑公式及相邻文字 (Priority: P1)

用户像编辑加粗、斜体一样在正文中修改行内公式。独立公式在正文原位置编辑，源码下方保留一处预览，用户可直接继续编辑相邻段落。

**Why this priority**　用户需要能输入、校对及删除公式，公式编辑应与普通输入衔接。

**Independent Test**　在有序列表中编辑 `1. 前文 $eee$ 后文`，再编辑连续两条独立公式。测试鼠标、方向键、Enter、Backspace、Delete、跨公式选区删除和撤销。

**Acceptance Scenarios**

1. **Given** 列表中有 `前文 $eee$ 后文`，**When** 点击公式或用键盘进入其文本范围，**Then** 原位置只显示一份可编辑的 `$eee$`，前后文字仍可继续输入。光标离开后，公式在原行原位置显示数学排版一次。
2. **Given** 文中含单行或多行 `$$` 独立公式，**When** 光标进入公式，**Then** 显露原有源码和定界符，并在源码下方显示至多一处预览。光标离开后，合法公式只保留一处排版。
3. **Given** 光标在 `$`、`$$`、`*` 或 `**` 的可编辑标记旁，**When** 按 Backspace、Delete 或删除包含它们的选区，**Then** 相应字符可以删除。失去配对或无法排版的公式保留剩余源码，可接着输入、移动光标、回车、撤销或完成编辑。
4. **Given** 用户刚编辑过格式或公式，**When** 直接点击下一段、在下一段按 Enter 或点击「完成」，**Then** 输入和导航直接生效，已经输入的内容进入正文自动保存流程。正文撤销与重做恢复对应文字、标记和相对位置。

### User Story 3 - 延续节点详情的保存和图表工作流 (Priority: P1)

用户继续在节点详情中加图片、调整图表位置、把图表或插入位置加入 DSH 草稿，并在重新打开节点后看到已保存内容。

**Why this priority**　已有笔记含混合内容，改进编辑键盘行为的同时需要保住已有资料、保存能力和 DSH 操作。

**Independent Test**　用一篇含图片、函数图、统计图、公式和已有 DSH 草稿的节点笔记，分别检查图片操作、图表移动删除、右键选点和自动保存重开。

**Acceptance Scenarios**

1. **Given** 笔记含一张图片、一张函数图和一张统计图，**When** 编辑相邻文字并保存、重开，**Then** 图片和图表保持显示，原来未编辑的内容以及图表数据和顺序保持原样。
2. **Given** 节点处于编辑状态，**When** 加入或删除图片，或拖动、删除任一图表，**Then** 仅目标引用或整张图发生变化。撤销恢复对应图片或图表，重做可再次应用该变化。图表的计算参数继续由 DSH 修改。
3. **Given** 原会话提问框已有草稿，**When** 右键使用「添加图表/公式」，或使用已有图表、文本引用入口，**Then** 对应内容进入原提问框且已有草稿保留，等待用户手动发送。正文中的文字点选与空白行均可用于既有定位流程。
4. **Given** 用户输入了有效正文变更，**When** 停止输入、切换或在保存后重新打开，**Then** 沿用自动保存与失败保护。在保存冲突发生时保留本地草稿，按既有流程处理外部版本。只读节点和离线导出的节点详情仍可阅读、复制和查看公式及图表。

### Edge Cases

- 公式、加粗和斜体相邻或嵌套时，各自按照其 Markdown 范围排版。转义标记、代码跨度、代码块里的示例、普通货币符号按项目现有语法识别。
- 最后一个列表项为空、从嵌套列表退回外层、列表项因侧栏较窄而视觉换行时，光标和修改以实际条目为准。
- 光标位于相邻两条公式之间，或选区跨标题、列表、公式与普通段落时，选区保持连续。跨越受保护图表的普通文本修改须明确反馈并保留图表，用户仍可通过整图操作修改位置或删除。
- 输入法组字期间或鼠标拖选时，正文及公式预览的刷新保持组合文字和有效选区。只有光标或选区变化时，正文及历史没有写入变更。
- 旧笔记使用 CRLF、混合换行、末尾空行或较长正文时，打开、移动光标及切换模式原样保留 Markdown。保存局部变更时保留周围未改动部分及图表定义。
- 插入位置或引用在发送前已发生变化时，沿用既有位置失效处理，无法唯一定位时保留原文并提示重新选点。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001** 保留「复制内容」旁的手动「编辑」入口和「完成」动作。节点标题、摘要和正文在原位置可改，模式切换保持当前可见段落。
- **FR-002** 节点正文采用连续的 Markdown 输入体验，保留正常的键盘导航、文字选择、复制、粘贴和中文输入。打开、预览和切换模式均不引起正文写入。
- **FR-003** 只读与编辑共用标题层级和正文排版规则。正文标题一至三级字号紧凑，颜色和字重与正文可区分，节点主标题保留更高的视觉层级。编辑时显露光标或选区所涉及内容的标记，离开后恢复排版。
- **FR-004** 标题、列表、加粗、斜体以及加粗斜体组合均可通过原位 Markdown 输入和修改。Enter、Backspace 与 Delete 按当前文本和列表层级生效，行内标记与普通字符均可删除。
- **FR-005** 行内公式在同一位置切换排版与源码，任一状态只出现一次。独立公式激活时在同一正文位置编辑原源码，源码下方至多显示一个预览。公式可通过方向键、点击、选区和删除键直接操作。未完成或无效公式按普通正文保留；跳转、退出和自动保存仍可继续。
- **FR-006** 保留节点图片的显示、加入、删除和撤销。编辑和只读均显示函数图和统计图。编辑时支持拖动或删除整图并撤销，普通文本操作保护图表数据，既有图表定义无需迁移。
- **FR-007** 保留既有 DSH 文本和图表引用、正文右键定位以及引用回跳。行内公式落在选中的文字点，图表或独立公式落在选中的段后，选空白行时使用该空白位置。加入引用保留草稿并由用户手动发送。
- **FR-008** 沿用已有自动保存批次、失败与冲突处理、同会话未保存草稿恢复、正文撤销和导图最多 30 步历史。图表移除及撤销仍遵守现有写入保护。
- **FR-009** 只读笔记及离线导出保持查看和复制能力，正文保留标题、公式、图片和图表的显示。离线详情仅提供阅读操作。

### Key Entities

- **节点正文**　属于稳定节点身份的 Markdown 文档，保留段落、标记、公式、图片引用和图表定义。
- **正文选区**　光标或一段被选中的正文范围，决定哪些标记显露以及编辑发生的位置。
- **图表与插入位置**　图表有原有的稳定身份。插入位置属于某个节点的正文，携带原会话引用需要的来源和定位信息。
- **编辑草稿**　当前正在编辑或等待保存的内容，沿用地图版本、保存批次和冲突处理流程。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001** 用同一篇笔记核对一至三级标题、加粗、斜体、加粗斜体和两类列表，共 8 项。8 项的非激活内容在阅读和编辑状态中均保持统一样式。10 次连续用鼠标或键盘进入、离开格式内容，光标均留在对应内容，且仅移动光标时原文没有变化。
- **SC-002** 复查 8 个编辑操作，涵盖列表续写、顶层空项目退出、嵌套空项目退出、相邻列表项退格合并、单行与多行粘贴、选区删除和中文组合输入。每项都保留预期文字、列表层级及光标位置。
- **SC-003** 在普通段落和有序列表内各核对一次行内公式，再核对单行和多行独立公式。每个用例能完成进入、修改或删除定界符、离开及撤销，行内无源码和公式重影，独立公式的额外预览最多 1 处，所有操作无需逐项确认。
- **SC-004** 验收图片加入删除、图表拖动删除、对应撤销重做及保存后重开。每项均只改动目标；重新打开后能看到已保存的修改，笔记中其余内容保持原样。连续执行 31 个有效的导图历史批次后，最近 30 步可撤销。
- **SC-005** 验收文字点、段落和空白行 3 种 DSH 插入位置，以及已有引用回跳。各次加入引用均保留现有草稿且没有提交消息，发送后落点符合规则。再分别模拟一次保存失败、一次外部冲突，均可找回本地草稿，外部冲突时外部版本没有被覆盖。

## Assumptions

- 适用范围为 DSH 桌面侧栏的节点详情正文。继续沿用现有配色和排版，只引入用户要求的实时预览交互。完整源码模式、Obsidian 专有 Markdown 扩展和插件兼容性超出本次范围。
- 合法 Markdown 格式使用现有笔记语法。阅读态与编辑态以同一侧栏宽度和缩放级别核对，光标激活时允许源码占用所需空间。
- 普通 Markdown 和临时写到一半的公式沿用已有正文写入规则。「完成」结束详情编辑，已保存编辑可通过现有撤销路径恢复。
- 导图历史和宿主关闭的恢复范围以[既有自动保存约定](../002-edit-layout-history/spec.md)为准。内部验收和 DSH 真机验收按项目授权执行。
