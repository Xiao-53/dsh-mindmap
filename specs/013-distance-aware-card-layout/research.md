# Phase 0 Research: 基于相连节点距离与结构规则的卡片初始排列优化

**Feature**: `013-distance-aware-card-layout` | **Date**: 2026-11-24 | **Spec**: [spec.md](spec.md)

---

## 0. 现有 `layout.ts` 初始排版局限性复盘

对照当前 [src/shared/layout.ts](../../src/shared/layout.ts) 与视觉基准 [docs/knowledge_atlas_demo_v17.html](../../docs/knowledge_atlas_demo_v17.html)，现行初始排布存在 4 处结构性局限：

1. **跨分组连线 100% 丢失**：
   - `placeBucketNodes` 第 20 行仅保留端点均在当前分组内的边：`relations.filter(e => e.fromNodeId !== e.toNodeId && indices.has(e.fromNodeId) && indices.has(e.toNodeId))`。
   - 当导图由多个分层或分阶段分组构成、分组内部少边或无边而主干连线跨分组连接时，`edges.length === 0`，算法直接退化为按数组下标从左到右盲排；即便上游节点在最右列，下游关联节点仍机械放回最左列，拉出全屏对角斜线。
2. **候选槽位锁死为前 $k$ 个紧凑格（`slots.length === memberIds.length`）**：
   - 组内有 4 个节点时（如 `1→2→1` 菱形或 `1→3` 一分三），槽位集合仅有第 0 行的 3 格与第 1 行的第 0 列（或奇数行右侧 `col = 2`），不存在“首行仅放 1 个并居中在 `col = 1`”或“末行单节点落在正中列”的候选位置。
3. **仅看离散 `(row, col)` 差值，缺少横向重心（Barycenter）微调与直线吸附**：
   - 面对如 HTML v17 `VIEW.root` 第 2 组（2 个节点 `ls`、`jj` 在 3 个前置节点下方对称居中对齐）或 `1→2` 分叉等不满 3 列行，现行坐标硬编码 `baseX + col * 327`，既无法对 2 节点行居中对齐到第 1/2/3 列间的重心，也无法主动触发 `012-simplified-edge-routing` 中的 `STRAIGHT_DEADZONE = 16` 垂直直线拉直。
4. **增量新增未定位节点未考虑已存相连邻居坐标**：
   - `fillLayout` 在遇到新节点时，从该组默认的 `x + 24, y + 62` 起按固定空位检测碰撞并不断 `n.y += height + 32` 下推，忽视该新节点与画布上已手动拖好位置的相邻节点之间的距离与依赖方向。

## 1. “相连节点距离目标 + 结构规则约束”混合模型 vs 纯物理力导向（FR-001, FR-006, FR-007）

### Decision
采用**两阶段确定性混合布局（Deterministic Distance-Rule Hybrid Layout）**：
- **Stage 1（拓扑层级种子 + 完整 $R \times 3$ 弹性网格联合距离寻优）**：
  - 在保持“同一分组聚拢、最大 3 列宽度、卡片零重叠、上下游流向优先、防同行/同列夹心直挡、四向枢纽居中”的规则约束下，综合**组内连线距离**与**跨组锚点距离**（$\sum w_e (\alpha |\Delta x| + \beta |\Delta y|)$，`dependency` 权重 `1.0`、`supplement` 权重 `0.6`）执行有限步确定性槽位分配与空槽移位/交换寻优；
- **Stage 2（受安全间距与走廊约束的横向重心连续微调与直线吸附）**：
  - 离散行列确定后，对不满 3 列的节点行按不同行相连邻居（含跨组锚点）的加权水平重心 $x^*$ 连续调整横向位置，并在偏差 $\le 48\text{px}$ 时精确吸附对齐以触发面对面笔直连线。

### Rationale
- **为什么不采用纯物理弹簧力导向（Force-Directed）**：节点卡片是宽 `236px`、高 `86～180px` 的带四向正交端口的矩形卡片且受分组容器约束。无网格/行列规则约束的纯弹簧布局会让卡片散落至任意斜角，导致分组框极大膨胀、大量卡片间无法触发面对面直线对齐，且高密度成环时容易振荡或产生杂乱斜线。
- **两阶段混合模型的优势**：Stage 1 用网格槽位守住“行列整洁、组框紧凑、防夹心、不重叠”的结构底线，同时将跨组/组内距离作为主导代价；Stage 2 在不破坏行序的前提下做像素级重心靠拢与直线对齐，使最终画面既有手工排版的对称感，又最大程度缩短连线距离并提升直连比例，单视图 $\le 20$ 节点总耗时 $< 1.5\text{ ms}$。

### Alternatives Considered
- **纯启发式网格加规则微调（不引入跨组坐标距离与重心微调）**：无法解决无组内边的分层跨组斜线问题，也无法让 2 节点行在 3 节点行下方居中对称，已排除。
- **引入 Dagre / ELK / 力导向第三方图布局库**：违反项目宪章第 IV 条“不额外引入图形库”的最小实现约束，且破坏 3 列紧凑分组视觉习惯，已排除。

## 2. 跨分组连线距离协同与紧凑分组框平移包裹（FR-002, FR-006）

### Decision
在 `fillLayout`（针对无已存布局的视图）与 `relayoutView` 中实行**两轮跨组协同排布（Two-Pass Bucket Coordination）**：
1. **前向传播（Pass 1 — 上游锚点约束下游）**：
   - 按 `buckets` 顺序逐组排布。排布当前分组 $B_k$ 时，构建 `anchors: Map<string, AnchorPoint>`，填入当前视图内已确定坐标的其他分组节点（以及同一视图未分组已定位节点）；
   - 将所有连接“$B_k$ 内节点 $\leftrightarrow$ 已定位跨组节点”的连线按真实像素距离纳入 `placeBucketNodes` 的离散槽位评分与 Stage 2 重心对齐中，使下游卡片自动向对应上游卡片的横向列位与重心靠拢。
2. **反向回看（Pass 2 — 下游对齐反哺上游）**：
   - 首轮各分组排布完成后，若前序分组内存在没有组内连线或重心偏移受下游牵引较大的节点（例如第 1 组 1 张卡连向第 2 组最右侧多张卡），以当前全视图所有跨组节点位置作为完整锚点，对有跨组连线的分组再执行 1 轮确定性协同微调（保持已有分组上下相对顺序不变），使上下分组双向呼应。
3. **紧凑分组外框跟随包裹**：
   - 保持 `left = Math.min(...inside.map(n => n.x - 24))`（当组内节点右移对齐到第 2/3 列而空出第 1 列时，1 节点或 2 节点小分组外框随节点坐标紧凑贴合包裹，1 节点组宽仍为 `284px`、2 节点组宽仍为 `611px`），不强行从 `x = 42` 撑出无效空白；
   - 在 `relayoutView` 的 `'grid'`（双列田字）模式下，先按跨组锚点协同排好各组内部相对顺序，再按分组盒总宽对齐并排放置，同时对左右相邻列中仅有跨列横向连线的分组节点以列偏移增量微调。

### Rationale
- 绝大多数分层导图采用“上游分组 $\to$ 下游分组”的自上而下排布，前向锚点即可消除 85% 以上的跨组大斜线；补充 1 轮轻量回看可解决“上游小分组仅 1～2 卡、下游大分组决定中心位置”的反向对齐场景，且全部分组坐标依然保持完全确定性与紧凑尺寸。

### Alternatives Considered
- **仅在纵向 `vertical` 模式启用跨组坐标感知，`grid` 模式忽略**：会导致切换双列田字排列时跨组连线退化回盲排，已排除；`grid` 模式将跨组锚点按各自在 `grid` 槽位中的预估横向偏移传入，实现双模式一致收益。

## 3. 弹性候选网格、分叉/汇合居中与横向重心直线吸附（FR-003, FR-004）

### Decision
1. **无连线退化保护（向后兼容）**：
   - 若分组内部**既无组内连线也无指向已定位锚点的跨组连线**，保持原数组顺序 `0, 1, 2, ...` 从左到右、从上到下平铺，100% 兼容既有孤立节点测试与用户直觉。
2. **弹性层级行与完整 $R \times 3$ 候选槽位池**：
   - 有组内或跨组连线时，先计算拓扑深度（对存在环路的图通过确定性最小入度/原下标破环保证有限步结束）：
     - 若拓扑结构明显呈“窄顶/窄底分叉汇合”（如 `1→2`、`1→3`、`2→1`、`1→2→1` 菱形，且按拓扑层划分总行数与紧凑 3 列行数差 $\le 1$），允许弹性分配每行容量，释放出首行居中单格 `(row=0, col=1)` 与末行居中单格 `(row=last, col=1)`；
     - 对于连续长链（如 6 节点串联 `n1→n2→n3→n4→n5→n6`），保持 3 列 S 型蛇形折行（偶数行左到右、奇数行右到左），避免把长流程拉成又细又长的单列“竹竿”。
   - 局部寻优支持**已占槽位成对交换**与**节点向空槽位单点迁移**（不超过 6 轮确定性最速下降），使离散位置既能避免夹心穿卡，又能让单节点或少数节点行自动落入居中或靠右对齐列位。
3. **Stage 2 横向重心连续微调与 `48px` 直线对齐吸附**：
   - 对当前行内节点数 $< 3$ 的每一行（在分组相对坐标 `[0, 654]` 走廊内，即标准 3 列卡片的左起点范围 `0` 到 `2 * 327 = 654`）：
     - 计算每个节点与**不同行相连邻居**（含组内上下行与跨组锚点）的加权目标水平中心 $x^*$（权重：`dependency = 1.0`, `supplement = 0.6`，垂直距离越近权重越高）；
     - 若该行仅有 1 个节点：将其横坐标钳位在 `[0, 654]` 内移向 $x^*$；若 $|x^* - x_{\text{anchor}}| \le 48\text{px}$（或距离某上下直接相连邻居的 `x` 偏差 $\le 48\text{px}$），直接精准吸附到该邻居的 `x`，从而在 `012` 路由下生成绝对垂直直线；
     - 若该行有 2 个节点：按列顺序依次满足最小同行间距 `MIN_ROW_STEP = 296`（`CARD_WIDTH 236 + 60px` 最小水平呼吸距，常规优先向标准格距 `327` 对齐）及左右边界 `[0, 654]`，先按两节点各自的目标重心对齐（如一卡对齐左列 `0`、另一卡对齐右列 `654`，或对称居中在 `163.5` 与 `490.5`），再检查是否与上下邻近节点处于 `48px` 直线吸附窗口内并无冲突吸附。

### Rationale
- 允许弹性行 + 空槽迁移彻底消除了“4 个节点第 1 行必须塞 3 个、第 2 行只剩 1 个被锁在最左列”的僵硬感；
- 横向重心连续微调与 `48px` 直线吸附直接复现了 HTML v17 原型中第 2 组（2 卡对齐第 1 组 3 卡间距中点）和 `1→2→1` 对称菱形的优雅几何，同时与 `012` 路由的 `STRAIGHT_DEADZONE = 16` 形成天然协同。

### Alternatives Considered
- **所有行严格锁死在 `col ∈ {0, 1, 2}` 三档离散坐标**：无法让 2 张卡在 3 张卡下方对称居中（只能偏左 `0, 327` 或偏右 `327, 654`），也无法精准对准被用户手动拖过的跨组父节点，因此增加 Stage 2 受约束连续微调。

## 4. 既有视图增量新增节点的关联邻居就近补位（FR-005, FR-008）

### Decision
在 `fillLayout` 中，当目标视图已存在部分已定位节点（`oldNodes.length > 0`）且存在新增未定位节点时：
1. **保护已存节点坐标**：`nodes` 中所有 `oldNodes` 原样保留（`manual` 标志与坐标零改动）；
2. **关联邻居优先落位**：对于每个未定位的新节点 $u$，收集其在该视图内所有**已定位的直接相连邻居**（优先 `dependency`，其次 `supplement`）：
   - 对每个邻居 $v$ 按关系方向生成 6 个顺向优先候选槽位（相对 $v$ 的当前位置）：
     - 若 $v \to u$（$u$ 是 $v$ 的后续下游）：依次尝试 $v$ 的右侧 `(v.x + 327, v.y)`、正下方 `(v.x, v.y + h_v + 32)`、右下方、左下方、正上方、左侧；
     - 若 $u \to v$（$u$ 是 $v$ 的前置上游）：依次尝试 $v$ 的左侧 `(v.x - 327, v.y)`、正上方 `(v.x, v.y - h_u - 32)`、左上、右上、右侧、下方；
     - 若仅为 `supplement` 补充关系：尝试两侧与上下对称紧邻位置；
   - 按“流向优先级惩罚 + 到所有已定位关联邻居的加权欧氏距离 + 是否超出原有分组区域边界的温和惩罚”对候选位置排序，选择首个与当前视图内全部已放节点满足防重叠安全距（水平/垂直净空 `24px`）的坐标；
   - 若新节点属于某个分组 $G$，该分组若在 `oldGroup` 中尚不存在则紧凑包络，若已存在 `oldGroup` 则按现有策略保留 `oldGroup`（或当未显式锁定且节点超出时仅保持 `fillLayout` 既有不改 `oldGroup` 契约，不破坏用户已保存分组框）。
3. **无邻居兜底**：若新节点在当前视图无任何已定位相连邻居，沿用原 `placeBucketNodes` 空位碰撞下移兜底。

### Rationale
- 既满足“新增节点出现在关联卡旁边最近顺向空位”，又严格遵守“绝不移动老节点、绝不静默改写既有 `oldGroup`”。

## 5. 带子图节点的单击画布选中与双击下钻分离（FR-009 / Clarification Q1 Option A）

### Decision
围绕 `drill = Boolean(node.childViewId && node.childViewId !== viewId)` 清晰拆分节点卡片交互，保持宿主侧栏与离线导出 100% 一致：
1. **画布仅选中动作 `selectNode(id)`（`useReadingNavigation.ts`）**：
   - 将状态更新为 `{ ...reading, selectedNodeId: id, detailHidden: true, focusSource: id }`（保持当前 `viewId`、`cameras` 与 `detailScroll` 不变）。
   - 效果：立即激活 `MapScene` 的 `.edges-focus` 与 `.edge-pill.is-focused` 提层高亮该节点的全部直接关联边与胶囊，同时由于 `detailHidden: true`，右侧 `NoteInspector` 保持关闭（若此前打开了其他叶子节点的详情面板也一并收起），保证用户单击或连续双击带子图节点时绝不会被抽屉弹出遮挡卡片或产生闪跳。
2. **卡片单击 / 双击 / 键盘交互映射（`NodeCard.tsx`、`MapScene.tsx`、`AtlasPane.tsx`）**：
   - `NodeCard` 保留 `onOpen`（下钻进入子图或打开叶子节点详情），新增可选 `onSelect?: () => void`（仅画布选中高亮）：
     - **`drill === true`（带可下钻子图入口的节点）**：
       - 鼠标单击 `onClick`：检查 `!locked && performance.now() >= suppressClickUntil.current`，调用 `onSelect?.()`（仅画布选中并提层高亮）；
       - 鼠标双击 `onDoubleClick`：检查 `!locked && performance.now() >= suppressClickUntil.current`，调用 `onOpen?.()`（触发 `nav.navigate(dest)` 0.5 秒平滑过渡进入子图；若动画 `locked` 进行中则自动忽略重复双击）；
       - 键盘无障碍：焦点在该卡片上按 `Enter` 调用 `onOpen?.()` 进入子图；按 `Space` 调用 `onSelect?.()` 选中高亮（避免空格键误跳转）。
     - **`drill === false`（无子图叶子节点，或子图视图中出现的自身中心节点）**：
       - 鼠标单击 `onClick`、`Enter` 与 `Space` 均保持现有直觉调用 `onOpen?.()` → `nav.openNote(id)`（选中卡片并展开详情面板；当详情已收起而画布仍选中时再次单击重新展开详情）。
   - 提示与语义更新：带子图节点的 `aria-label` 与右上角提示图标 `title` 更新为清晰反映新交互（例如 `aria-label="选中节点，双击进入内部思维导图：..."` / `title="双击进入子图"`），既准确表达操作预期，又保留测试与屏幕阅读器可定位性。
3. **拖拽保护**：
   - 节点指针拖拽结束时设置 `suppressClickUntil.current = performance.now() + 190`，并在 `onDoubleClick` 同样检查 `performance.now() >= suppressClickUntil.current`，防止拖动松手偶发连带点击被误判为双击下钻。
4. **双端一致**：
   - `src/client/offline.tsx` 直接渲染 `ReadingPane → MapScene → NodeCard`，无需任何额外修改即自动获得完全一致的单/双击行为。
