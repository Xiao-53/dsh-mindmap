## 0. 既有代码与 v17 原型静检结论

结合当前仓库 [edge-geometry.ts](../../src/shared/edge-geometry.ts)、[animate-ports.ts](../../src/client/animate-ports.ts)、[MapScene.tsx](../../src/client/components/MapScene.tsx) 与 [prototype-parity.test.ts](../../tests/shared/prototype-parity.test.ts) 的源码审读及对 [knowledge_atlas_demo_v17.html](../../docs/knowledge_atlas_demo_v17.html) 的静检，确认现状存在以下关键事实与结构性根因：

1. **端口法向 $G^1$ 未锁死（导致箭头根部与端口出口折角）**：
   - `connectionGeometry` 虽然在终点留出了 `3px` 轴向直线段 `stem` 接入箭头，但在单段避让与三段避让中调用 `shiftPoint(c1, offset)`、`shiftPoint(c2, offset)` 对控制点施加弦法向偏移，再以 `clampOutward(..., 12)` 兜底；当侧移较大时，进入 `stem` 的切向量与端口法线形成明显夹角，导致箭头根部与起点圆点出口出现可见折角或斜擦卡片边界。
2. **基础弧度在远距与转角处缺乏收敛上限**：
   - 邻边或同边连线使用 `bend = Math.max(24, Math.hypot(end.x - a.x, end.y - a.y) / 2)`，跨组远距斜连或转角连线会拉出高达数百像素的巨大外弧鼓包；而对边当两卡极近或轻微反向错位时，`midX`/`midY` 容易使控制点缩回起终点卡片内部。
3. **仅按 `coreHits > 0` 触发避让且忽略起终点自身卡片**：
   - 现行代码先按 `Math.min(10, dim / 4)` 向内收缩得到核心盒 `core`，仅当 20 个固定采样点命中 `core` 时才触发避让，导致擦切卡片边框或圆角时完全不避让；同时过滤掉了 `a.nodeId` 与 `b.nodeId`，无法拦截大幅绕行或转角时曲线折返切入自身卡片。
4. **写死 460px / 160px 阈值、$t=1/3, 2/3$ 切分与 `±248px` 上限**：
   - `LONG_EDGE_LENGTH = 460` 与 `MIN_TRIPLE_LENGTH = 160` 仅按像素长度切段；航点锁定在 $t=1/3, 2/3$ 且最大法向偏移限死在 `±248px`（微调上限 `280px`），面对偏心单障碍、大宽/高障碍簇或斜跨水平/垂直走廊时常出现“多余弯曲”或“偏幅不够仍穿卡”；
   - 三段连接点采用 `m1 * m2 > 0 ? ... : 0` 修正，遇到需要先向一侧绕再向另一侧绕的反弯路径（$m_1 \cdot m_2 \le 0$）时切向修正归零，导致连接点出现拧巴急折。
5. **孤立逐边计算、固定标签点位与无状态翻转**：
   - `createConnections` 与 `useAnimatedPorts` 逐条孤立调用 `connectionGeometry`，导致多条绕过同一障碍同侧的边或双向互连在绕行时完全重合；标签固定取 `cubicMidpoint(segs[1])`，易被相邻卡片遮盖；拖拽经过障碍中线时离散候选无滞回保护，存在高频翻侧闪烁风险。
6. **v17 原型兼容性基线**：
   - 对 `docs/knowledge_atlas_demo_v17.html` 全视图执行脚本静检（节点高度 `110px`），绝大部分连线无中间卡片阻挡；仅 5 条隔卡连线存在路径遮挡（`root`: `quantum -> spin`、`ls`: `interaction -> compare`、`ls`: `ls_step -> j_examples`、`quantum`: `orbital -> ls`、`term`: `degeneracy -> example`）。因此无阻挡连线可 100% 保持 v17 端口选边与柔和曲线特征，仅阻挡连线启用本次避让与正面直挡智能换边。

## 1. 端口外法线 $G^1$ 锁定与无阻挡基础弧度收敛（FR-001 / FR-002 / SC-001）

### Decision
1. **全程强制端切向与端口法线共线（绝对 $G^1$ 无折角）**：
   - 定义四向单位外法向量：
     $$\vec{u}(\text{side}) = \begin{cases} (-1, 0) & \text{left} \\ (1, 0) & \text{right} \\ (0, -1) & \text{top} \\ (0, 1) & \text{bottom} \end{cases}$$
   - 无论曲线最终为 1 段、2 段还是 3 段，首段第一控制点与末段最后控制点**严格限制在对应端点的外法线射线上**：
     $$C_{1,1} = P_s + h_s \cdot \vec{u}_s, \qquad C_{m,2} = P_e + h_e \cdot \vec{u}_t \qquad (h_s \ge h_{\min} > 0,\; h_e \ge h_{\min} > 0)$$
   - 其中 $P_s = (a.x, a.y)$ 为输出圆心，$P_e = (b.x + n_x (r_{\text{in}} + L_{\text{arrow}} + 3),\, b.y + n_y (r_{\text{in}} + L_{\text{arrow}} + 3))$ 为衔接 `3px stem` 尾端的曲线终点；因此曲线出口垂直于起点卡片边缘、曲线末端与 `stem` 及箭头方向 $180^\circ$ 共线平滑衔接，彻底消除肉眼可见折角。
2. **基础单段曲线分 4 类按真实几何收敛弧度（无阻挡场景）**：
   - **对边正向连接**（`left↔right` 且正向跨度 $d_\parallel = (P_e - P_s)\cdot\vec{u}_s > 0$，或 `top↔bottom` 同理）：
     - 若轴向净距充足（$d_\parallel \ge 16$），保留 v17 经典的 $h_s = h_e = d_\parallel / 2$（等价于控制点落于 `midX` / `midY`），当横向错位不大时呈现经典柔和 S 形；若跨度很长且横向错位明显，加入轻微上限 $\min(d_\parallel / 2,\; \max(0.45\|P_e - P_s\|, 220))$ 防止超长边在端口处过度拉平再猛拐；
     - 若起终点极近或轴向反向重叠（$d_\parallel < 16$），保底外伸 $h_s = h_e = \text{clamp}(28 + 0.35|d_\perp|,\; 24,\; 96)$，防止控制点缩入起终点自身卡片内部。
   - **邻边转角连接**（如 `bottom↔left`、`right↔top`）：
     - 将起点到终点在双方出射正方向上的投影距离记为 $p_s = \max(0, (P_e - P_s)\cdot\vec{u}_s)$ 与 $p_t = \max(0, (P_s - P_e)\cdot\vec{u}_t)$；
     - 采用接近四分之一椭圆平滑弧的收敛系数 $\kappa = 0.55$：
       $$h_s = \text{clamp}(\max(0.55 \cdot p_s,\; 0.25 \cdot L),\; 22,\; 180), \qquad h_e = \text{clamp}(\max(0.55 \cdot p_t,\; 0.25 \cdot L),\; 22,\; 180)$$
       （其中 $L = \|P_e - P_s\|$），既消除了现行 `length / 2` 导致的远距巨型鼓包，又避免近距急折僵硬。
   - **同侧端口拱桥连接**（用于正面直挡换边或同向环回，如 `top→top`、`bottom→bottom`）：
     - 沿出射侧方向先抬高过较高一侧卡片外沿的差值，设两端口沿外法线方向的差值 $\Delta_{\text{out}} = (P_e - P_s)\cdot\vec{u}_s$，拱桥基础抬高 $A_0 = \text{clamp}(0.22 \cdot L_\perp + 24,\; 34,\; 112)$，则：
       $$h_s = A_0 + \max(0, \Delta_{\text{out}}),\qquad h_e = A_0 + \max(0, -\Delta_{\text{out}})$$
       确保双控制点位于同一高度水平/垂直支撑线上，形成对称饱满且贴边顺滑的大拱弧。
   - **自环连接**（`self === true`）：
     - 保持在卡片右侧独立成环（或沿已有分布的 `a.y` 与 `b.y` 上下外伸），起点按外上 `(-15°~-25°)` 与终点严格沿 `right` 法线水平入箭头的方式（或使用锁定端口外法线的 2 段独立外环），确保自环出口与箭头入口均无折角、输出空心圆与输入实心圆清晰分离且绝不压盖卡片标题文字。

### Rationale
- 从几何构造上彻底把“端口方向约束”与“避让偏移自由度”正交解耦：无论后续采用 1 段、2 段还是 3 段，外部只调整手柄长度 $h_s, h_e$ 与中间航点，绝不横向歪斜拉偏首末控制点，从而在根本上保证了 **SC-001（100% 端切向顺滑无折角）** 与 **FR-004（防起终点自身卡片擦边）**。

### Alternatives Considered
- **仅加大 `clampOutward` 最小前伸阈值（如从 12px 增至 32px）**：仍允许控制点斜偏法线，在大幅绕行时依然会在 `3px stem` 处产生可见折角，已淘汰。
- **改用正交圆角折线（Orthogonal Rounded Polyline）**：破坏 HTML v17 柔和圆润的视觉风格，不符合项目宪章第 V 条，已淘汰。

## 2. 双层卡片安全包络、自身卡片防回穿与自适应弧长采样（FR-003 / FR-004 / Q3）

### Decision
1. **三级非端点安全包络与自身卡片防穿透边界**：
   - 将所有非端点卡片统一预处理为 `CardEnvelope`：
     - `card`：完整可见矩形 $[x,\, x + w] \times [y,\, y + h]$（0px 穿卡即属硬碰撞）；
     - `pad`：外扩克制留白 `CLEARANCE_PAD = 7px`（处于澄清 Q3 约定的 `6～8px` 正中），作为触发避让与常规路径优选的安全边界；
     - `core`：内缩 `min(10, dim / 4)` 矩形，仅在极端密集无法完全避开 `card` 时作为最小遮挡降级权重（避免穿卡切穿卡片文字核心区）。
   - 对起终点自身卡片 `a.nodeId`、`b.nodeId` 构建 `SelfCardGuard`：
     - `selfA`：对首段 $t \le 0.03$ 的极近端口微段豁免（避免把从边框圆点垂直引出的起点误判为碰撞），首段 $t > 0.03$ 及后续所有分段均禁止穿过 `[a.x + 1, a.x + a.w - 1] × [a.y + 1, a.y + a.h - 1]`；
     - `selfB`：由于曲线终点 $P_e$ 位于 `b` 卡片外沿 `15px`（$r_{\text{in}} + L_{\text{arrow}} + 3$）处，全程禁止任何分段穿过 `b` 的完整矩形 `[b.x, b.x + b.w] × [b.y, b.y + b.h]`。
2. **控制多边形 AABB 快速剪枝 + 按长度自适应密集采样**：
   - 每段三次贝塞尔 $[P_0, P_1, P_2, P_3]$ 严格落在其 4 个控制点构成的轴对齐包围盒（AABB）内；检测碰撞前先用控制多边形 AABB 与卡片包络做 $O(1)$ 快速排斥，绝大多数不相邻卡片直接跳过；
   - 通过剪枝的段按控制折线总长 $L_{\text{poly}} = \|P_1 - P_0\| + \|P_2 - P_1\| + \|P_3 - P_2\|$ 动态计算采样点数：
     $$N = \text{clamp}\!\left(\lceil L_{\text{poly}} / 12 \rceil,\; 8,\; 48\right)$$
     保证即使 1200px 超长边相邻采样点间距也 $\le 12\text{ px}$，同时检测采样点与卡片边界的**最大穿透深度 `maxCardDepth` / `maxPadDepth`**，既消除边角漏检，又为 Q3“最小绕行改动”提供精准的脱出偏移量度。

### Rationale
- `CLEARANCE_PAD = 7px` 恰好兼容 `src/shared/layout.ts` 的 `32px` 最小行距与 `91px` 最小列间距（`327 - 236 = 91px`）：两卡垂直留白合计 `14px`，行间通道仍留有 `18px` 干净走廊，不会误触发无障碍连线；
- 在采样层面加入精确穿透深度，使得轻微擦边时可以直接算出“刚好脱出留白所需的最小偏移（如 `10px` 或 `18px`）”，严格兑现 Q3 的最小绕行改动要求。

### Alternatives Considered
- **固定 20 点采样**：在 `800px+` 长跨度连线上采样步长超过 `40px`，容易漏判卡片圆角或窄边缘切割，已淘汰。
- **使用精确解析方程求线段/贝塞尔与矩形交点**：计算复杂度与分支数显著上升，且在连续多段、需同时返回最大侵入深度和外侧走廊净空时收益不如凸包 AABB 剪枝 + 12px 步长采样稳健高效。

## 3. 仅正面直挡时的智能端口换边规则（FR-005 / Q1 Option B）

### Decision
在 `createConnections` 分配端口阶段（排序同侧端口之前）引入**正面直挡判定与智能换边评估**：
1. **严格限定触发前置条件（防止一般场景乱换边）**：
   - 仅当 `self === false`、初始分配为**对边端口**（即水平 `right↔left` 或垂直 `bottom↔top`），且满足以下全部条件时才触发换边评估：
     - 两端点卡片在垂直于连线方向的轴上存在投影重叠或近正对（水平边：两卡 $Y$ 区间交集 $\ge 0$ 或中心 $|\Delta y| \le \max(a.h, b.h) \cdot 0.65$；垂直边：两卡 $X$ 区间交集 $\ge 0$ 或中心 $|\Delta x| \le \max(a.w, b.w) \cdot 0.65$）；
     - 至少存在一张非端点卡片位于 $a$ 与 $b$ 之间，且基础直连曲线在 `card` 内部产生**深度正面阻挡**（穿透中心或横向/纵向侵入 `card` 深度 $\ge \min(18,\, 0.25 \cdot \text{cardDim})$）。若仅轻微擦过某张卡片边缘（不构成正面堵死），**绝对不换边**，交由原端口下的最小微幅绕行处理。
2. **换边候选评估与选择标准**：
   - 水平正面直挡（原 `right↔left`）仅评估 `top→top` 与 `bottom→bottom` 两套同侧拱桥端口方案；
   - 垂直正面直挡（原 `bottom↔top`）仅评估 `left→left` 与 `right→right` 两套同侧拱桥端口方案；
   - 对原方案与两套换边拱桥分别做轻量化 Stage 0/1/2 路由（使用对应端口中心估算位置与相同障碍集）；
   - **切换判据**：仅当某换边拱桥同时满足：
     1. 换边后不再碰撞任何卡片且不回穿起终点自身（`selfHits === 0 && cardHits === 0`）；
     2. 原端口方案若留守则必须急折绕行（原方案存在穿卡，或原方案最大拐角更陡且总绕行弧长明显劣于拱桥，考虑滞回阈值后 `switchScore + SWITCH_MARGIN < keepScore`，其中 `SWITCH_MARGIN = 16` 等价于原侧轻度偏好，避免临界轻微优势就乱跳边）。
3. **与既有同侧端口排序及平滑动画无缝对接**：
   - 换边结果直接写入对应 `Port.side` 后再进入既有的 `groups` 同侧 `projectedOrder` 防交叉排序与 `place(group)` 均匀分布；
   - 当用户拖动卡片进入或离开正面直挡区间时，`useAnimatedPorts` 既有的 `180ms` 卡片边缘环形滑轨动画会把圆点从 `right/left` 沿边框圆角丝滑滑到 `top/bottom`，连线弧线同步从直连变为拱桥。

### Rationale
- 完全兑现 Q1 Option B：常规无阻挡和一般斜向连接 100% 保持既有四向动态端口选边（保护 v17 布局直觉），只有同排/同列隔卡正面堵死时（如同排 `A — B — C` 中 `A → C` 被 `B` 堵死）才滑向顶/底边架起自然拱桥，视觉效果比在 `91px` 窄缝里硬折 90° 拐角干净得多。

### Alternatives Considered
- **永久锁死四向初选侧边**：`A — B — C` 在紧邻间距下被迫从 `A` 右侧出线贴脸急转 `90°` 向上再急转绕回 `C` 左侧，极易打结且压占旁路间隙，已由 Q1 澄清排除。
- **任意受阻均自由比较全部 $4 \times 4 = 16$ 端口组合**：计算开销大且容易因微弱布局变化让端口在四边乱跳，破坏阅读稳定性，已排除。

## 4. 取消写死三段：障碍驱动的 1～3 段自适应升级与向心平滑样条（FR-005 / FR-006 / Q2 Option B / Q3）

### Decision

#### 4.1 废除硬编码阈值，建立 4 级自适应路由阶梯（严格封顶 1～3 段）
彻底移除 `LONG_EDGE_LENGTH = 460`、`MIN_TRIPLE_LENGTH = 160`、`t = 1/3, 2/3` 固定切割及 `±248px` 硬上限，改由实际碰撞与障碍几何驱动升级：

1. **Stage 0 — 无阻挡基础单段（0 航点 / 1 段）**：
   - 构造符合第 1 节 $G^1$ 锁死规范的 1 段基础曲线；
   - 若 `selfHits === 0 && cardHits === 0 && padHits === 0`，直接结束返回。**零多余弯折、零额外计算**。
2. **Stage 1 — 1 段锁法向手柄调优（0 航点 / 1 段）**：
   - 当存在擦碰/穿卡且起终点为**同侧端口（拱桥）或邻边转角**，或者基础斜线仅发生单侧轻微擦边时：
     - **同侧拱桥**：按沿途障碍高度外延精确计算抬升高度，同步增大 $(h_s, h_e)$ 把拱顶抬过障碍安全包络即可，天然保持对称单弧，无需拆成多段；
     - **邻边/斜向微擦**：以锁定法向方向为前提，在有限几组非对称手柄比例 $(h_s, h_e)$（缩小或适度拉长某一端控制臂）中寻找刚好脱出碰撞盒且弧度最小的 1 段解。若得到 `selfHits === 0 && cardHits === 0 && (padHits === 0 || 最小微让优于多段)` 的光滑单段解且无明显过绕，即止步于 **1 段**。
3. **Stage 2 — 障碍驱动的 1 航点自适应绕行（1 航点 / 2 段）**：
   - 当 1 段无法洁净绕过（常见于对边直连擦边、单张阻挡卡或同侧多卡组成单一障碍簇），先对命中卡片及紧邻卡片做**障碍聚类**：若两张命中/邻近卡片的间距小于 `2 * CLEARANCE_PAD = 14px`（即中间没有可容曲线平滑穿过的走廊），自动合并为一个联合包围盒 `ObstacleCluster`，消除“两卡紧贴硬挤缝隙”的畸形走线；
   - 为候选走廊生成紧致且全覆盖的 **1 航点（2 段）候选集**：
     - **通道 A（最小微推点，专治 Q3 轻微擦边）**：取基础曲线穿透最深采样点处，沿垂直于弦的方向刚好移出 `card` 外沿 `CLEARANCE_PAD`（以及紧贴走廊时的最小外沿 `2px`）形成单一航点；偏幅常仅 `8~28px`，视觉上几乎保持原有单段顺滑弧度而优雅让开边角；
     - **通道 B（障碍簇四向包络外侧点）**：对命中障碍簇外扩 `CLEARANCE_PAD + 半线安全余量`，在障碍簇中心弦投影两侧生成上下/左右安全绕行航点（偏幅随真实障碍包围盒尺寸自适应计算，**完全不受原 `248px` 上限束缚**）；
     - **通道 C（相邻卡片间隙走廊中点）**：若基础弦两侧存在两张相邻但未合并的卡片且缝隙 $\ge 14\text{ px}$（甚至仅 $\ge 6\text{ px}$），取两卡间隙中心作为航点，使曲线优雅穿缝而不强行绕过外围大圈；
   - **1 次安全外推微调**：由于平滑样条穿过航点时邻近弦段可能存在轻微内切/外凸超调，若 2 段候选存在极轻微残余 `cardHits`，将航点沿外离障碍中心方向追加 `+8px / +16px` 微调复检，迅速消除擦边；
   - 若已得到简洁无碰撞（`selfHits === 0 && cardHits === 0`）且满足最小绕行代价的 2 段方案（即使在极窄走廊仅保留 `2~6px` 贴框净空），即止步于 **2 段**，不再强切 3 段。
4. **Stage 3 — 障碍驱动的 2 航点自适应绕行（2 航点 / 3 段封顶）**：
   - 仅当 Stage 2（2 段）仍存在 `selfHits > 0` 或 `cardHits > 0`（常见于：1）单张极宽或极高卡片导致 2 段斜穿其顶角；2）沿途存在 2 张及以上沿连线方向错位分布的障碍簇需要连续越过或 S 形穿隙；3）障碍紧靠起/终点端口出口需要先出再拐）时启用：
   - 基于真实障碍几何生成约 12～24 组高质量 `(W1, W2)` 航点对（非盲目穷举）：
     - **宽/高单簇包络双角点**：在阻挡簇沿连线方向入口与出口外侧生成同侧双角航点 $(W_{\text{enter}}, W_{\text{exit}})$，让中段平稳贴着安全走廊平行掠过宽/高卡片而不会出现大尖顶；
     - **沿弦序错位双簇通道组合**：按沿连线投影从起点到终点排序主要障碍簇，分别从第一簇上/下外侧与第二簇上/下外侧（或间隙走廊）组合 `(W1, W2)`，支持同侧外绕（U 型走廊）与顺畅 S 形穿隙；
     - **近端口脱困点**：若首/末段因相邻卡紧贴端口而受阻，为 $W_1$ 或 $W_2$ 补充“沿端口外法线出框后横向拐出”的预出射航点，防回穿起终点自身卡片。
   - **冗余航点精简（兜底保持最少段数）**：若 3 段候选成功，额外检测删去 $W_1$ 或 $W_2$ 后的 2 段结果——若 2 段同样无碰撞且弯折代价更低，自动退回 2 段；
   - **极端密集降级（FR-006）**：若在 3 段上限内仍不存在无碰撞路径（如节点彼此重叠或无通道），在所有已评估的 1～3 段候选中按严格字典序选出确定性降级解：
     $$\text{selfHits} + \text{cardHits} \;\rightarrow\; \text{coreHits} \;\rightarrow\; \text{maxCardDepth} \;\rightarrow\; \text{detourRatio} + \lambda_{\text{bend}} \cdot \text{bendEnergy}$$
     （其中 $\lambda_{\text{bend}} = \text{LAMBDA\_BEND} = 0.32$），确保永远输出完整、有限坐标且遮挡最小的克制曲线。

#### 4.2 向心弦长加权平滑样条（消除拧巴急弯与反弯点退化）
给定起点 $Q_0 = P_s$、航点序列 $Q_1, \dots, Q_{k}$（$k \in \{1, 2\}$）与终点 $Q_{k+1} = P_e$：
1. 记各折线段向量 $\vec{d}_i = Q_{i+1} - Q_i$，弦长 $L_i = \max(1,\, \|\vec{d}_i\|)$，单位方向 $\hat{d}_i = \vec{d}_i / L_i$；
2. 对每个内部航点 $Q_i$（$1 \le i \le k$），采用**向心弦长权重** $\alpha = 0.5$（即 $\sqrt{L}$ 反比加权）融合前后切向：
   $$\vec{t}_i = \sqrt{L_i}\,\hat{d}_{i-1} + \sqrt{L_{i-1}}\,\hat{d}_i, \qquad \hat{\tau}_i = \begin{cases} \vec{t}_i / \|\vec{t}_i\| & \|\vec{t}_i\| > 10^{-6} \\ \hat{d}_i & \text{否则} \end{cases}$$
   （若采用双角点绕行同一宽/高障碍单边且相邻线段接近平顺，向心切向会自动自然对齐走廊方向；且无论同号绕行还是异号 S 形反弯，切向均连续平滑、**绝不再出现旧版 `m1 * m2 <= 0` 导致的切向归零拧结**）。
3. **转角自适应控制臂长度**：
   - 计算 $Q_i$ 处前后方向夹角余弦 $c_i = \text{clamp}(\hat{d}_{i-1} \cdot \hat{d}_i,\; -1,\; 1)$；
   - 转角越缓（$c_i \to 1$）臂长系数越舒展，转角越急（$c_i \to -1$）臂长适度收敛以防反弯自交环或过度甩出碰撞卡片：
     $$\rho_i = 0.34 \cdot \text{clamp}(0.75 + 0.25 c_i,\; 0.52,\; 1.0)$$
     $$Q_i\text{ 前手柄} = Q_i - (\rho_i L_{i-1})\,\hat{\tau}_i, \qquad Q_i\text{ 后手柄} = Q_i + (\rho_i L_i)\,\hat{\tau}_i$$
   - 首端从 $Q_0$ 严格沿 $\vec{u}_s$ 出射，首手柄长度 $h_s = \text{clamp}(0.38 L_0 \cdot \max(0.45, \vec{u}_s \cdot \hat{d}_0),\; 18,\; \min(0.48 L_0, 140))$；
   - 末端到 $Q_{k+1}$ 严格沿 $\vec{u}_t$ 反向汇入，末手柄长度 $h_e = \text{clamp}(0.38 L_k \cdot \max(0.45, -\vec{u}_t \cdot \hat{d}_k),\; 18,\; \min(0.48 L_k, 140))$（极近时按 $\min(h, 0.55 L)$ 自适应缩容，杜绝过冲）。
4. **“最小绕行改动”综合代价函数（Q3）**：
   - 硬约束优先级：`selfHits`（越低越好） → `cardHits`（越低越好）；
   - 在窄缝或轻微擦边权衡中引入软留白惩罚，而非把 `padHits` 设为不计成本的硬一刀切：
     $$\text{cost} = \text{detourExcess} + \text{LAMBDA\_BEND} \cdot \text{bendEnergy} + 8 \cdot \text{segmentPenalty} + 2.5 \cdot \text{maxPadPenetration} + \text{hysteresisBonus}$$
     - 其中 `LAMBDA_BEND = 0.32`、`segmentPenalty = segments.length - 1`（取值 `0 | 1 | 2`），`detourExcess = max(0, splineLength - baseLength)` 直接衡量绕行多出的路程；轻微擦边移出 `12px` 的 `detourExcess` 不到 `3px`，而强行绕一大圈的 `detourExcess` 高达 `180px+`；
     - `bendEnergy` 惩罚不必要的拐点总转角与多段冗余起伏；
     - `maxPadPenetration` 对侵占 `7px` 留白但 `cardHits === 0` 的路径仅施加轻度温和惩罚（宽裕走廊内自动选择留足 `7px` 的解；窄走廊内若满足满 `7px` 必须大绕远，则 `detourExcess` 自然胜出，自动维持紧贴卡片外框外侧的最小平滑微让）。

### Rationale
- 从“盲目 121 次法向网格试错”演变为“几类几何确定的走廊候选 + 统一向心平滑样条”，既实现了 **Q2 Option B（1～3 段自适应封顶）**、**Q3（最小绕行改动）**，又大幅减少了每帧候选评估次数，使整体计算反而比旧版更快。

### Alternatives Considered
- **完整 A* / Visibility Graph 任意多边形寻路**：容易产生 4～8 段锯齿状路径、动态拖拽时拓扑跃迁频繁且违反 Q2 3 段封顶要求，已排除。
- **保持现行 De Casteljau 三等分偏移并仅放宽 `248px` 上限**：仍无法针对偏心障碍、斜向水平/垂直间隙走廊生成准确航点，且无法消除端口与反弯点折角，已淘汰。

## 5. Pass-2 共路与双向边轻量轨道分层（FR-007 / Q4 Option A / SC-003）

### Decision
在 `routeSegments` 完成所有边的 Pass-1 独立避让求解后，执行轻量 Pass-2 轨道分层：
1. **分组归类**：
   - **共路绕行组**：Pass-1 记录了绕行元信息 `bypassClusterKey`（所绕主要障碍簇 ID，或跨间隙走廊两卡有序对 `idA|idB`）与 `bypassSide`（`top | bottom | left | right | + | -`）的边，按 `(bypassClusterKey, bypassSide)` 聚合；
   - **双向 / 同对多关系组**：对尚未被上述同一共路组包含的边，按无序端点对 `{min(from, to), max(from, to)}` 聚合（当同一对节点间存在 $\ge 2$ 条边，且二者使用同侧或对称近距路径产生中段接近重合时）。
2. **组内确定性排序与自适应分层间距（Q4 Option A）**：
   - 每组按“法向垂直轴坐标均值 → 端口次序 → `relation.id`”排序，得到组内共 $k \ge 2$ 条边，相对索引偏移 $r_i = i - (k - 1) / 2$；
   - 测量该走廊沿分离方向上的真实可用净空 $W_{\text{avail}}$（若一侧贴近其他非端点卡片安全区，精确测得该走廊上下/左右两卡片内壁之间的净间隙；若处于全图最外侧开阔区域，则 $W_{\text{avail}} = \infty$）；
   - 按 Q4 Option A 计算分层步距 `gap`：
     $$\text{gap} = \begin{cases} 10 & W_{\text{avail}} = \infty \text{ 或 } W_{\text{avail}} \ge 2 \cdot \text{minEdgeGap} + 10(k - 1) \\ \text{clamp}\!\left(\dfrac{W_{\text{avail}} - 2 \cdot \text{minEdgeGap}}{k - 1},\; 4,\; 10\right) & \text{窄缝自适应收紧} \end{cases}$$
     （其中 `minEdgeGap = 4px`；无论多窄都不低于 `4px` 可分辨间距，若窄缝净空极限不足也不将多余连线挤去障碍卡片另一侧或更外圈绕大圈，只在该走廊内紧凑并行）。
3. **重算路径与安全核验**：
   - 对每条边将其航点（对 Stage 0/1 的双向并行直连边，若尚未有航点则补 1 个中点微弧航点）沿走廊分离法向平移 $r_i \cdot \text{gap}$ 并重调 $G^1$ 样条；
   - 验证偏移后的曲线未因超出安全范围而撞入非端点卡片 `card` 或自身卡片（若外侧贴卡片太近，将该条偏移量按 `card` 边界内回夹至安全最大余量）。

### Rationale
- 将“单边几何寻路”与“多边关系协调”拆为清晰的 Pass-1 / Pass-2 两阶段，既能一次性分离同障碍同侧的 2～4 条绕行线与双向互连边，又能严格恪守“不挤去对侧绕大圈”的约束，计算量仅为少量涉及分组边的单次样条重建。

### Alternatives Considered
- **在 Pass-1 中逐边把已路由的曲线离散线段当成障碍物**：结果强烈依赖边数组输入顺序，且容易连锁放大后画线条的绕行弧度导致越绕越远，已排除。
- **固定 `12px` 分层且溢出分流到卡片对侧**：直接违背 Q4 Option A 与 Q3 最小绕行改动原则，已淘汰。

## 6. 关系文字标签防压卡动态择优定位（FR-008 / SC-003）

### Decision
仅对带有非空 `relation.label` 的边（绝大多数无标签边零开销跳过）执行标签锚点搜索：
1. 估算标签占用视觉包围盒尺寸（计入 `MapScene` 固定在 `labelY - 8` 居中绘制 `<text>` 且有 `6px` 描边白底的特征）：
   - 按字符宽度（中文/全角约 `11px`、ASCII 约 `6.5px`）计算 `boxW = clamp(estWidth + 12, 34, 180)`，`boxH = 18`，中心放在 `(cand.x, cand.y - 8)`。
2. 在最终生成的多段曲线上按**总弧长 25%～75% 区间**等距取 9 个候选点（优先避开靠近端口圆点与箭头根部的 0%～25% 和 75%～100% 区域）；
3. 对每个候选点计算：
   - `overlapArea`：标签包围盒与当前视图**全部节点卡片（含端点卡片）**矩形的重叠面积之和；
   - `curvature`：该点处局部切向量变化率（偏向平缓弧段，避免字横在急转弯上）；
   - `centerBias`：距弧长中点 `0.5` 的偏离度（无障碍时自然居中，与 v17 一致）。
4. 若全部在线上候选均与某卡片存在轻微重叠（`overlapArea > 0`），额外测试沿曲线该点局部单位法向偏移 `±10px` 后的贴线候选位置（仍紧靠曲线旁），按 `(overlapArea → curvature → centerBias)` 字典序返回最优 `label: { x, y }`。

### Rationale
- 保留 `MapScene` 现有 `<text className="edge-label" x={labelX} y={labelY - 8}>` 渲染接口零改动，同时把“固定居中易压卡”升级为“沿着曲线可读中段滑移避卡”，能稳定满足 **SC-003（$\ge 90\%$ 标签完整避开卡片遮挡）**。

### Alternatives Considered
- **对每条绕行线固定取中段贝塞尔中点**：在 2 段路径中段点刚好落在拐点，在 3 段跨卡路径中文字易压住相邻分组节点，已淘汰。

## 7. 拖拽临界区轻度滞回与动画帧全链路共用（FR-009 / Q5 Option A / SC-004）

### Decision
1. **纯客户端瞬态记忆结构 `EdgeRouteHint`（不落盘、按 `viewId` 隔离）**：
   - 定义 `EdgeRouteHint = { sourceSide: Port['side']; targetSide: Port['side']; bypassSide?: 'top' | 'bottom' | 'left' | 'right' | '+' | '-' }`；
   - 在 `MapScene.tsx` 中用 `useRef<{ viewId: string; map: Map<string, EdgeRouteHint> }>` 维护，切换 `view.id` 时自动清空。
2. **仅在拖动过程中启用轻度临界缓冲（滞回）**：
   - 将 `MapScene` 已有的 `dragging` 状态传给路由选项 `{ hints, dragging }`；
   - 在智能换边（Q1）与避让侧选择（Stage 2/3）对比“延续上一次 `bypassSide` / `portSides` 的无碰撞候选”与“切换到对侧的新候选”时：
     - 只要原侧候选依然满足 `selfHits === 0 && cardHits === 0`（不穿卡！），对切换到相反侧的候选追加 `HYSTERESIS_COST = 24` 的等效代价门槛（对应拖过障碍中线约 `±12px` 的滞回缓冲带）；
     - 若用户继续拖动并明确越过缓冲带（新侧净优势 $> 24$），立即一次性切到新侧并刷新 `hints`；
     - **安全性优先原则**：若原侧一旦开始发生穿卡（`cardHits > 0` 或 `selfHits > 0`），滞回立即失效，立刻平滑切换到无碰撞侧，杜绝“为了防闪烁而在拖拽中短暂穿卡”。
3. **抽离 `routeSegments` 供 `createConnections` 与 `useAnimatedPorts` 共享**：
   - 将所有避让、共路分层、标签避卡和滞回逻辑统一封装在批量函数 `routeSegments(segments, nodes, options)` 中；
   - `createConnections` 在完成端口分配和换边后直接调用 `routeSegments`；
   - `useAnimatedPorts` 在每一帧补间插值 `ports` 后不再逐条单独调用 `connectionGeometry`，而是调用同一 `routeSegments`（传入 `nodes` 与 `{ hints, dragging }`），使得 180ms 端口滑轨动画帧里的弯曲、绕行、共路错开和文字标签与静态画面 100% 连续同步。

### Rationale
- 直接满足 **Q5 Option A（拖动全程实时避让 + 中线临界区轻度滞回）** 与 **SC-004（缓慢拖过障碍中线仅切换 ≤ 1 次且端/线/箭头 100% 同步贴合）**。
- 性能预算：按 20 节点、30 条边估算，Pass-1 单边无阻挡约 0.005ms，单边 2/3 段避让约 0.03～0.08ms，Pass-2 + 标签定位约 0.1ms，整视图全量重算控制在 **1～2 ms** 以内，远低于 `16.6ms`（60fps）帧预算。

### Alternatives Considered
- **拖拽期间冻结绕行方向并等 `onDragEnd` 再重算**：用户拖着节点时旧线会穿卡或绕远路，松手瞬间突然跳变，违背 Q5 Option A。
- **使用全局持久化状态记录绕行侧**：违反项目宪章第 II 条与 `FR-011`（不修改 `layout.json` 与 `map.json`），已排除。
