# Feature Specification: 节点连线曲线弧度与避让逻辑优化

**Feature Branch**: `main`（沿用当前工作分支）
**Created**: 2026-11-23
**Status**: Draft
**Input**: User description: "优化节点连线的曲线弧度与避让逻辑"

## Clarifications

### Session 2026-11-23

- Q: 当两张相连节点卡片处于同排或同列，且默认连线端口正前方被另一张中间卡片直接挡住时，连线是否应保持原有端口侧边只靠曲线绕行，还是允许自动改选更顺畅的卡片侧边（如改走顶边/底边跨过）? → A: 采用仅正面直挡时允许智能换边（Option B）：无阻挡的常规与斜向连线完全保留现有四向动态端口选边规则；仅当默认端口正前方被中间卡片直接堵死、原侧出线必须急折绕行时，才自动改选阻力更小的侧边（如顶边/底边）并平滑过渡跨过。
- Q: 当一条连线沿途存在一张或多张挡路卡片需要弯折绕行时，曲线的分段数量应当如何决定? → A: 采用 1～3 段自适应并封顶（Option B）：取消写死三段与按固定长度强切，由沿途实际阻挡与走廊复杂度自动选用 1 段、2 段或最多 3 段平滑曲线（无阻挡或轻度单侧微绕保持 1 段，单障碍优先 1～2 段，多障碍按需升至最多 3 段）；若 3 段仍无法完全绕开极端密集障碍，则直接走最小遮挡确定性降级，避免出现多次连续弯折的蛇形线。
- Q: 连线经过其他卡片附近时，应当在多近的距离触发避让并保留怎样的视觉留白? → A: 采用卡片完整外框加克制留白（约 6～8px）统一触发与避让（Option A），并严格遵循“最小绕行改动”原则：仅轻微擦碰卡片外框或留白边缘时，只对原平滑曲线施加刚好足以脱出留白边界的最小微幅偏移，不强行绕一大圈、不因轻微擦边折出多个大弯或触发不必要换边；当走廊偏窄无法无代价满足完整留白时，优先保持最小幅度贴外框平滑微让，而非为硬凑满留白而大幅绕远。
- Q: 当多条连线同时绕过同一张挡路卡片同侧或经过同一卡片间隙时，共路连线的分离应当采取哪种策略? → A: 采用共路与双向边均自动分层、窄缝内自适应收紧间距（Option A）：空间充裕时保持清晰分层间距，走廊较窄时按可用净空压缩间距紧凑并行，不强行将多余连线挤到卡片另一侧或更外圈绕大圈，同时满足可分辨与最小绕行改动原则。
- Q: 当用户持续拖动一张节点卡片经过其他连线或卡片中线附近时，实时避让与防闪烁应当如何平衡? → A: 采用实时避让加临界区轻度滞回缓冲（Option A）：拖动全程实时更新完整避让弧线；当卡片接近障碍中线等临界区时通过窄缓冲带保持当前绕行侧，明确越过缓冲带后再一次性切到更优侧，既保持跟手实时避让又抑制来回高频闪烁。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 顺滑自然的曲线弧度与无折角端口衔接 (Priority: P1)

用户在思维导图画布上阅读各类布局关系（包括紧邻卡片、斜向错位连接、邻边转角连接以及跨分组长距离连接）时，每一条节点连线都以柔和、克制、弧度协调的圆润曲线呈现。连线从起点卡片的输出圆点沿垂直于卡片边缘的方向自然引出，并沿垂直于终点卡片边缘的方向顺滑对准箭头尖端汇入，在圆点出口与箭头根部均不出现突兀斜插、生硬折角或紧贴卡片边框滑擦的瑕疵；当路径上无其他卡片阻挡时，曲线保持简洁流畅的单弧或柔和 S 形形态，既不在近距离时弯折过急，也不在远距离或转角连接时拉出失比例的过度鼓包。

**Why this priority**: 连线的曲线观感与端口出入射顺滑度是用户看懂整张导图关系脉络的视觉基础，直接决定是否延续既定视觉基准（HTML v17）的柔和美学，也是所有避让绕行保持优雅可读的前提。

**Independent Test**: 构造覆盖水平正对、垂直正对、轻微错位、大幅斜向、邻边转角（如底边连左边、右边连顶边）、近距紧邻、远距跨组及自环连线且无中间卡片阻挡的标准视图，逐一目视与测量检验：所有连线的输出出口与箭头入口衔接顺滑无可见折角，弧度随间距与错位程度协调收敛，无过度鼓包，且不回擦起终点自身卡片边框。

**Acceptance Scenarios**:

1. **Given** 两张节点卡片处于水平、垂直或斜向错位位置且中间无其他卡片阻挡，**When** 画布渲染二者之间的连线，**Then** 连线以顺滑圆润、弧度克制的平滑曲线连接，起点沿垂直于卡片边缘的方向自然离开输出圆点，终点沿箭头方向顺滑汇入输入圆点外沿，在圆点出口与箭头根部均无可见折角。
2. **Given** 两张节点卡片通过相邻侧边相连（例如上方卡片底边连向侧方卡片左边，或右侧边连向顶边）且间距较近或较远，**When** 画布渲染该转角连线，**Then** 曲线弯折幅度随起终点实际距离自适应收敛，近距不僵硬急折、远距不向外撑出过大鼓包，且曲线不擦入起终点自身卡片的边角。
3. **Given** 一张节点卡片存在指向自身的自环关系，**When** 画布渲染自环连线，**Then** 自环在卡片外侧形成清晰圆润的独立回环，输出空心圆与输入实心圆分离可辨，箭头指向准确，不压盖卡片标题或摘要文字。

### User Story 2 - 完整边界避让、多障碍平滑绕行与自身卡片防穿透 (Priority: P1)

当两张相连节点之间存在一张或多张其他节点卡片阻挡时（包括同排隔卡直连、同列隔卡直连、跨组斜穿多张卡片，或用户手动拖动卡片挡住既有连线），连线能够主动避开挡路卡片的完整可见边框并留出清晰可读的视觉留白，不再擦边切割卡片边框或圆角；同时连线在转折或绕弧时也不会反过来擦入或穿过自身起点卡片或终点卡片的内部。遇到沿途存在多张交错排列卡片（含较宽或较高卡片）的长跨度连线时，连线能够自动选择净空更充裕的卡片外侧或卡片间隙通道连续平滑绕过，全程弧度自然流畅，不出现生硬尖角、不必要的多余波浪扭曲，也不会因绕行幅度不足而放弃避让直接穿卡。

**Why this priority**: 消除“连线穿卡、擦边压字、多障碍绕行生硬失真或绕不过去”是本需求的核心痛点；一旦连线压盖卡片主体或绕行形态杂乱，会直接干扰用户阅读卡片内容并破坏导图结构清晰度。

**Independent Test**: 构造包含“同排隔一张宽卡”、“同列隔多张高卡”、“默认曲线仅擦过中间卡片圆角/边框”、“长跨度斜穿多张交错卡片（1～3 段可通行走廊）”以及“极端密集无通道重叠卡片”的测试视图，分别验证静态打开与手动拖拽造阻挡两种方式：存在可通行走廊时连线 100% 避开所有非端点卡片完整边框（含视觉留白）及起终点自身卡片，全程弧度平滑；极端拥挤无通道时稳定降级为遮挡最小的确定性路径且不产生异常畸变或远甩飞线。

**Acceptance Scenarios**:

1. **Given** 两张相连节点之间存在一张中间节点卡片，无论原曲线穿过卡片中心区域、明显阻挡还是仅轻微擦碰该卡片的外框或 6～8px 留白边缘，**When** 画布渲染该连线，**Then** 连线严格遵循最小绕行改动原则触发避让——若仅轻微擦碰边缘，只对原平滑弧线做刚好脱出边界的最小幅度微调，不绕大圈、不折多个大弯也不触发多余换边；若处于同排或同列且默认出口被正面直挡、原侧出线必须急折绕行，则允许自动改选更顺畅的卡片侧边（如改走顶边或底边）并平滑滑动端口形成自然大拱弧跨过；其余一般阻挡场景沿净空更优的一侧以最小必要绕幅平滑绕过该中间卡片的完整外框并保留清晰视觉留白（走廊偏窄时优先最小幅度贴外框平滑通过），不切割卡片边界或压盖卡片内容。
2. **Given** 一条跨列或跨分组长连线的路径上存在一张或多张交错排列的中间卡片（含高度或宽度较大的卡片），**When** 画布生成避让曲线，**Then** 连线不再写死三段或仅按固定长度强切，而是按沿途实际阻挡卡片与间隙自动选用最少必要的 1 段、2 段或最多 3 段平滑曲线连续绕过全部阻挡卡片，全程弧度自然流畅、无尖锐拐角和多余波浪抖动，且不因过小固定偏幅限制而过早放弃避让。
3. **Given** 连线因大幅绕行或邻边连接需要在起终点卡片附近形成较大弯曲，**When** 画布渲染该连线，**Then** 曲线不折返切入自身起点卡片或终点卡片的内部区域，并保持起点出口与终点箭头入向的顺滑衔接。
4. **Given** 视图处于极端密集或节点卡片彼此紧贴重叠的状态，不存在任何 1～3 段平滑曲线内可完全避开全部卡片的通道，**When** 画布渲染连线，**Then** 系统以确定性策略在 1～3 段内选择对卡片主体遮挡面积最小、曲线形态最克制的降级路径，保证连线、端点圆点和箭头完整可见且无失控飞线。

### User Story 3 - 多条绕行连线分离、关系标签防遮挡与拖动稳定性 (Priority: P2)

当视图中有多条连线同时绕过同一张中间卡片的同一侧、或共同穿过两张卡片之间的同一走廊（含两节点间的双向互连或多条并行关系）时，各条曲线能够保持清晰可分辨的视觉间距分层错开，不再彼此完全叠合成一根线导致无法判断连线数量与去向；带有文字名称的关系连线在绕行后，关系文字紧随实际绕行曲线停留在可读弧段旁，并优先避开节点卡片遮挡；当用户用鼠标持续拖动节点卡片时，连线弧度与绕行路径实时平滑跟随，在障碍卡片中线等临界位置附近保持方向稳定，不出现高频反复左右/上下跳变闪烁，并与端点沿卡片边缘的滑动过渡严密同步。

**Why this priority**: 单条线的弧度与避让达标后，真实复杂导图中最直接影响可读性与手感的痛点就是多线叠合难追踪、关系标签被盖住或脱离曲线，以及拖拽卡片时线条在两侧疯狂闪烁跳变。

**Independent Test**: 构造“3 条连线绕过同一张挡路卡片同侧”、“两张卡片双向互连且中间有阻挡”、“带文字标签的多条绕行长边”以及“鼠标缓慢拖着卡片横穿另一条连线中线”的场景，验证共路连线清晰分离可逐条辨识、标签随曲线可读且避开卡片遮挡、拖拽过程中方向稳定不闪烁且端口圆点与箭头全程严密贴合，同时在深浅色主题和离线导出独立阅读页中复核一致。

**Acceptance Scenarios**:

1. **Given** 两条及以上连线需要绕过同一张中间卡片的同侧，或共同穿过两张卡片之间的同一间隙走廊，**When** 画布渲染这些连线，**Then** 各条连线自动分层错开且互不完全重合粘连——空间充裕时保持清晰可分辨的独立间距，走廊偏窄时按可用净空自适应收紧间距紧凑并行，不为了凑宽间距将部分连线强行挤到障碍卡片另一侧或更外圈绕大圈，用户可顺着任意一条曲线清晰辨识其起终点归属。
2. **Given** 一条带有关系名称文字的连线因中间卡片阻挡而绕弧避让，**When** 画布渲染该连线及文字标签，**Then** 关系文字紧随实际绕行后的曲线定位在可读弧段旁并优先避开节点卡片遮挡，不残留在原直连位置或被挡路卡片盖住。
3. **Given** 用户按住一张节点卡片缓慢连续拖动，使其穿过其他连线路径或接近另一张卡片中线位置，**When** 节点坐标连续微幅变化，**Then** 拖动全程实时计算并平滑更新完整避让弧线；当接近障碍中线等临界位置做小幅晃动时，经由轻度滞回缓冲维持当前绕行侧不闪烁，明确越过临界缓冲带后再一次性切到更优侧，且端点圆点、曲线主体与箭头始终严密贴合、无脱节或错位。
4. **Given** 用户选中某节点以高亮直接关联连线并淡化无关连线，或将当前导图导出为离线独立阅读页并在浅色/深色主题下打开，**When** 查看画布中的各类连线，**Then** 曲线弧度、避让路径、共路分离与关系标签位置在宿主侧栏与离线阅读页中完全一致，且所有已保存的节点和分组位置保持原样不变。

### Edge Cases

- **零间距或极近相邻卡片**：当两张相连卡片被手动拖至边缘几乎相贴甚至部分重叠时，连线仍保持有效几何呈现，不出现断裂、消失、方向倒刺或异常巨环。
- **高度差异悬殊的卡片**：当同一行或相邻区域同时存在单行简短卡片与长摘要高卡片时，避让边界基于每张卡片的实际呈现尺寸计算，不会按默认估算高度误切高卡片下半部分。
- **高连接度枢纽节点**：当单个节点某一侧集中了 4 条及以上输入/输出端口并同时触发绕行避让时，各条连线在近端口处保持清晰展开不绞结，且同侧端口防交叉排序继续保持有效。
- **双向互连与同对多关系**：当两张卡片之间同时存在反向连线或同时存在主要依赖与补充关联时，无论路径上有无中间阻挡卡片，多条连线与各自标签均清晰分离、互不遮盖。
- **跨分组连线与分组标题区域**：连线跨越不同分组时可自然穿过半透明分组背景框，不将整个分组容器误判为不可进入的实心障碍，避免产生不必要的超大幅度外绕。
- **既有布局保护与大图流畅性**：打开任意已有保存布局的导图时，连线优化绝不改写或漂移原有节点与分组坐标；在包含 20 个节点、30 条以上连线的复杂视图中，打开与连续拖拽卡片仍保持流畅无明显卡顿。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 画布节点连线 MUST 延续既定视觉基准（HTML v17）的柔和圆润曲线风格，并保证每条连线在输出端点处沿垂直于起点卡片边缘的方向自然引出、在输入箭头前沿垂直于终点卡片边缘的方向顺滑汇入，消除端口出口与箭头入口处的突兀斜插、尖锐折角或紧贴卡片边缘滑擦现象。
- **FR-002**: 无中间卡片阻挡的常规连线（含水平、垂直、斜向、邻边转角及跨分组长距离连线）MUST 根据起终点相对位置与距离自适应收敛弧度，保证近距不急折僵硬、远距不产生失比例过度鼓包，且曲线不回擦起终点自身卡片边框。
- **FR-003**: 当连线路径穿过或擦碰视图内任意非端点节点卡片的完整可见外框及其克制视觉留白安全区（约 6～8px）时，系统 MUST 按“最小绕行改动”原则触发避让——仅轻微擦边时 MUST 只施加刚好让出边界的最小幅度平滑微调，不得因轻微擦边而绕一大圈、折出多个大弯或触发不必要换边；当卡片间隙偏窄、硬凑完整留白会迫使曲线大幅绕远时，优先以最小改动贴卡片外框外侧平滑通过，而非强行绕远。
- **FR-004**: 避让判定与绕行曲线生成 MUST 同时防止连线折返擦入或穿过自身起点卡片与终点卡片的内部区域，确保起终点卡片自身边界与内容不受连线压盖。
- **FR-005**: 常规无正面直挡场景 MUST 保留既有四向动态端口选边规则不变；当同排或同列默认端口正前方被中间卡片直接挡住、原侧出线必须急折绕行时，系统 MUST 允许自动改选阻力更小的卡片侧边（如改走顶边/底边或左/右侧）并配合端口边缘滑动平滑过渡。避让曲线 MUST 取消写死三段及纯长度硬切限制，改为按沿途实际阻挡与通道复杂度在 **1 段、2 段至最多 3 段** 之间自适应选用最少必要段数（单障碍优先简洁的 1～2 段，多张交错阻挡按需扩展至最多 3 段），系统 MUST 评估卡片外侧与可行卡片间隙通道的净空与绕行代价，生成全程弧度平滑连续、克制自然、无尖锐拐角且无不必要波浪扭曲的绕行曲线，不因过小固定偏幅限制而过早放弃避让。
- **FR-006**: 在卡片极度密集、相互重叠，或 3 段平滑曲线上限内不存在完全无碰撞路径的极端布局下，系统 MUST 按确定性降级规则在 1～3 段范围内选择对非端点卡片主体遮挡最小、弧度最克制的路径，不得出现连线消失、路径畸变或失控飞线。
- **FR-007**: 当多条连线（含双向互连或共用通道的跨卡连线）绕过同一张挡路卡片同侧或共同穿过同一卡片间隙走廊时，系统 MUST 对共路连线施加可分辨的视觉间距分层，防止多条曲线完全叠合成单一线条；在走廊宽度偏窄时 MUST 按可用净空自适应收紧分层间距紧凑并行，不得为了硬凑宽间距将部分连线强行挤到障碍另一侧或更外圈绕大圈。
- **FR-008**: 当带有关系名称文字的连线发生曲线绕行时，关系标签 MUST 紧随实际绕行后的曲线停留在可读弧段旁，并优先避开节点卡片区域的遮挡，保持标签清晰可读且归属明确。
- **FR-009**: 在用户连续拖动节点卡片以及端口沿卡片边缘滑动过渡期间，受影响连线的弧度与完整避让路径 MUST 全程实时平滑更新，并在障碍中线等临界位置通过轻度方向滞回缓冲保持稳定性（小幅微调维持当前绕行侧，明确越过缓冲带后再一次性切到更优侧，抑制高频来回翻转闪烁），同时保证端点圆点、曲线主体与箭头始终严密贴合。
- **FR-010**: 自环连线、主要依赖实线、补充关联虚线及选中节点触发的关联连线焦点高亮/淡化效果 MUST 完整兼容优化后的曲线与避让规则；输入端点（雾霾蓝实心圆）、输出端点（灰豆沙空心圆及 2px 描边）及箭头停靠输入圆外沿的既有视觉规范保持不变。
- **FR-011**: 本次曲线弧度与避让逻辑优化 MUST 完全基于视图内节点当前实际尺寸与坐标实时计算，不得改写任何已保存的节点或分组位置，不得改动现有导图内容与布局的存储格式，且 MUST 在宿主桌面侧栏（含浅色/深色主题）与离线导出的独立阅读页中呈现完全一致的效果。

### Key Entities

- **节点连线（Node Connection）**: 视图内表达两节点之间（或节点自身）有向关系的曲线元素，包含起点输出圆点、终点输入圆点与指向箭头、曲线路径、关系类型样式（主要依赖/补充关联）及可选关系名称标签。
- **卡片安全包络（Card Clearance Envelope）**: 基于每张节点卡片实际渲染尺寸向外扩展视觉留白构成的避让边界，用于判断连线是否穿卡、擦边或回穿自身起终点卡片。
- **绕行通道与共路集合（Detour Corridor & Shared-Corridor Group）**: 卡片外侧或相邻卡片之间可供连线平滑穿行的净空区域，以及经过同一绕行区域的多条连线集合，用于协调多线错开间距、避免视觉粘连。
- **关系标签锚点（Edge Label Anchor）**: 依附于实际连线曲线可读弧段的文字放置位置，随曲线绕行实时调整并尽量避开节点卡片遮挡。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在涵盖水平、垂直、斜向、邻边转角及跨组长连线的无阻挡标准验证集（不少于 15 种典型相对位置组合）中，**100%** 的连线在输出端点出口与输入箭头入口处衔接顺滑无可见折角，且 **0 条** 连线回擦自身起终点卡片边框或出现失比例过度鼓包。
- **SC-002**: 在涵盖单卡正挡、单卡轻微擦边、高/宽卡片阻挡、多卡交错阻挡且存在 1～3 段可通行平滑走廊的标准避让验证集（不少于 12 个场景）中，连线穿过或压入非端点卡片完整可见外框的比例降至 **0%**（在走廊充裕场景下同步保持约 6～8px 视觉留白，且轻微擦边场景 100% 通过最小微幅弧度调整解决、不产生绕大圈或多段大折弯），回穿自身起终点卡片的比例降至 **0%**。
- **SC-003**: 在 2 至 4 条连线绕过同一障碍卡片同侧及两节点双向互连的测试场景中，**100%** 的共路连线保持清晰可分辨的独立间距、不发生完全叠合；所有带文字标签的绕行连线中，至少 **90%** 的标签完整避开节点卡片遮挡并紧邻对应曲线清晰可读。
- **SC-004**: 在包含 20 个节点、30 条连线的复杂视图中，用户连续拖动节点穿过其他连线与卡片周边时，画布响应流畅无明显掉帧，端点圆点、曲线与箭头 **100%** 同步贴合无脱节；单次缓慢拖过障碍中线临界区时绕行侧切换不超过 **1 次**（无高频来回闪烁）。
- **SC-005**: 打开既有已保存布局的导图时，所有节点与分组坐标保持率 **100%**；在宿主桌面侧栏（浅色与深色主题）以及离线导出的独立阅读页中，同一视图的曲线弧度、避让轨迹、共路分离与标签定位一致率 **100%**。

## Assumptions

- **仅正面直挡时允许智能换边**：遵循项目宪章与 HTML v17 视觉基准，常规无正面直挡场景完全保留既有四向动态端口选边（上/下/左/右动态选边与同侧防交叉分布）与 HTML v17 端口位置习惯；仅在同排或同列默认出口被中间卡片正面直挡时，允许自动改选更顺畅的卡片侧边并平滑滑动过渡。
- **延续柔和圆润曲线美学**：保持 HTML v17 柔和流畅的曲线视觉语言，不改为直角正交折线或硬折角连线风格。
- **避让对象聚焦节点卡片**：避让检测面向视图内所有节点卡片的实际渲染外框与视觉留白（含起终点自身卡片防回穿）；半透明分组背景框允许跨分组连线自然穿过，不作为实心不可进入障碍。
- **保持轻量零重型依赖**：遵循项目宪章最小实现原则，连线优化在现有轻量呈现体系内演进，不引入外部重型图形或连线路由库。
- **零持久化格式破坏与既有布局只读**：所有弧度调节、避让与多线分离均属于实时视图呈现逻辑，不向导图结构或布局文件新增必填路由字段，也不改写用户已保存的节点或分组坐标。
- **侧栏与离线导出共享呈现规则**：宿主侧栏（浅色/深色主题）与离线导出的独立阅读页复用同一套连线呈现逻辑，确保双端一致。
