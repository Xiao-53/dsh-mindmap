**Status**: Draft

## Clarifications

### Session 2026-11-19

- Q: 对于脱离笔记引用的孤儿图片，以及已作废或已永久删除的空壳导图目录，系统应当在什么时机执行清理? → A: 采用延迟安全回收（Option B）：孤儿图片在当前编辑会话结束或用户显式清理且确认全图无引用后删除（保留编辑期间撤销/恢复能力）；已作废/已永久删除目录平时保留防复活标记，仅在用户触发清理或接近工作区目录列举上限时按安全规则回收最旧已完结记录目录。
- Q: 当用户在侧栏正在编辑节点正文、拖动布局或核对某条引用定位时，若 AI 后台刚刚完成建图或改图并触发自动跳图，系统应当如何协调? → A: 采用静默保护与轻量提示（Option B）：编辑、拖拽或引用核对期间不强行自动跳转也不清除当前引用定位，改用轻量通知提供手动“查看更新”入口；空闲浏览不同导图时才自动打开，且所有外部跳转统一经过未保存保护。
- Q: 当用户通过局域网 HTTP 等非安全上下文访问 Web 版 DSH 时，插件应当如何处理编辑保存、图片上传与正文位置捕获? → A: 移出范围、不兼容非安全上下文（Option C）：插件仅面向桌面端及本地/HTTPS 安全上下文运行，不为局域网或远程非加密 HTTP 访问提供额外兼容回退。
- Q: 当用户在节点笔记中点击本地非图片附件链接（如 PDF 或 TXT 文件）时，系统应当采用哪种打开方式? → A: 精简为仅支持本地图片资源（Option C）：不再支持在节点笔记中挂载、内联读取或打开本地 PDF/TXT 等非图片附件；遇到此类非图片本地链接时仅显示只读提示而不触发无效内联打开，也不将其大体积内容载入导图快照。
- Q: 本轮 `009` 架构健壮性加固希望一次性覆盖哪几个优先级范围? → A: 全部覆盖 P1 + P2 + P3（Option A）：一次性纳入宿主兼容隔离、事务删除/目录与孤儿图片回收、监听与内存边界控制、防打断跳转/macOS 快捷键，以及 Windows 路径规范化与工具失败状态对齐。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 宿主升级与运行边界兼容隔离 (Priority: P1)

当宿主应用（DSH）发布新版本、调整内置共享校验与运行时组件版本、变更部分非核心服务可用性，或者工作区/其他插件存在同名命令或能力时，思维导图插件仍能安全启动或局部降级，不会拖垮宿主整体启动，也不会让对话主界面白屏或无响应。

**Why this priority**: 宿主兼容或依赖隔离失效会直接造成整套软件崩溃或不可用，是最高风险的隐患类别，必须优先彻底消除同类问题。

**Independent Test**: 模拟宿主共享校验版本小幅升级、非核心服务暂不可用、事件数据结构小幅变更或存在同名技能/工具的场景，验证插件启动与宿主主界面仍保持可用，受影响能力降级并给出清晰提示，未出现未捕获异常传播至宿主根部。

**Acceptance Scenarios**:

1. **Given** 宿主升级了内部共享基础库或调整了非关键客户端依赖拓扑，**When** 插件随宿主启动并加载，**Then** 插件不会因强行钉死单一精确依赖版本而引入冲突副本导致宿主或插件崩溃，且所有直接依赖的宿主能力均明确声明在插件清单中。
2. **Given** 宿主工具参数校验规则更新或远端通道暂未就绪，**When** 插件初始化服务端或客户端能力，**Then** 初始化过程对异常进行边界隔离，局部能力不可用时仅禁用对应功能并提示用户，不影响宿主的常规对话与侧栏其他页签。
3. **Given** 宿主会话事件流中出现结构微调或未知事件项，**When** 插件监听当前会话以实现自动打开或引用回跳，**Then** 插件能够安全跳过无法识别的字段或条目，不抛出未捕获运行时错误。
4. **Given** 工作区或其它扩展中已存在同名技能标识，**When** 插件注册自身辅助能力，**Then** 插件能够给出可预期的冲突处理或明确诊断，不静默破坏用户对导图能力的使用。

### User Story 2 - 事务删除、目录容量与资源生命周期闭环 (Priority: P1)

用户在长期使用中反复创建导图、在笔记中上传并替换图片、清理未完成创建记录以及从回收站永久删除导图时，工作区导图目录与附件保持整洁且状态一致：不会因为目录残留只增不减最终触及列表上限而彻底无法浏览导图，也不会因回收站索引与文件删除之间状态错位导致永久删除后卡在不可恢复的错误状态，且孤立的本地资源能被有序清理。

**Why this priority**: 数据一致性破坏或导图目录上限锁死会导致用户既有知识资产无法读取或管理，属于不可接受的高危数据与可用性隐患。

**Independent Test**: 在工作区中连续执行多轮创建、上传并删除笔记图片、失败创建清理以及多选永久删除操作（包括在永久删除写回索引阶段模拟并发目录变更），验证目录列表始终可正常打开、回收站状态一致可恢复，且不再使用的资源能够按规则回收。

**Acceptance Scenarios**:

1. **Given** 用户从回收站批量永久删除多张导图，且部分或全部导图文件已被删除但期间目录索引发生并发变更，**When** 系统更新目录索引失败，**Then** 系统能基于持久化的删除状态自动对齐或安全重试完成状态收敛，不会让用户反复看到“文件已消失但条目仍卡在回收站且无法重试”的死锁状态。
2. **Given** 用户多次执行创建失败清理和永久删除，**When** 清理或永久删除完成后，**Then** 系统在工作区目录数量处于安全范围时继续保留防复活标记；当用户显式触发历史记录清理或接近宿主目录列举上限时，系统发出预警并按安全规则回收最旧且确认无未知内容及无活动事务的已完结记录目录，避免目录积累导致整个导图库无法列出。
3. **Given** 用户在节点笔记中移除了某张本地上传图片的引用并保存，**When** 当前编辑会话仍保留撤销历史时，**Then** 该图片文件暂予保留以支持撤销恢复；待编辑会话结束（或用户显式触发资源清理）且确认全图已无任何节点引用时，系统安全回收该孤儿图片文件。
4. **Given** 节点笔记中存在指向本地 PDF、TXT 等非图片附件的链接，**When** 系统加载并渲染该节点详情时，**Then** 系统不将此类非图片文件内容整份内联进导图快照，界面仅展示不可用的只读链接提示，不再生成会被浏览器安全策略拦截的无效内联链接。

### User Story 3 - 文件监听缩放、大导图载荷与内存边界控制 (Priority: P2)

当工作区累积了数十张导图、单个导图包含几十个节点笔记与多张大图片，或用户长时间使用并频繁切换多个会话和导图时，插件的资源占用保持在合理可控范围内：文件变更监听不会随文件数成倍消耗连接并频繁报错，大导图打开与保存不会因重复全量读取和载荷膨胀而卡顿超时，内存中的临时缓存也会按生命周期及时清理。

**Why this priority**: 随着真实使用深度增加（多导图、大图文、长会话），目前的设计会在无明显外部操作时逐渐恶化为卡顿、监听失败提示与内存持续上涨，直接影响日常稳定性。

**Independent Test**: 构造包含 30 张以上导图的工作区及包含多张大图和几十个节点的单张导图，在连续打开、切换会话、反复关闭页签与预览修改后，检查文件监听数量、单次打开读取量以及内存缓存条目数均保持有界且界面操作流畅。

**Acceptance Scenarios**:

1. **Given** 工作区存在大量导图或单张导图包含大量笔记与附件，**When** 用户停留在导图库或打开该导图时，**Then** 插件不会在短时间内重复触发冗余列表刷新，也不会因对每个文件无节制建立独立监听而触发连接上限导致“文件观察不可用”错误提示。
2. **Given** 一张导图包含多张较大尺寸的图片，**When** 用户打开导图或保存局部文字修改，**Then** 传输与校验机制不会产生远超单图限制的不可控整体载荷或不必要的全量重复加载，若总体积接近传输上限应有明确的前置提示与保护。
3. **Given** 用户在多个会话之间频繁打开、编辑、预览删除并关闭导图或将导图永久删除，**When** 会话关闭、导图删除或预览超过时效时，**Then** 内存中保留的编辑会话快照、布局草稿、删除预览授权记录及路径缓存能够及时淘汰释放，不会无限增长。

### User Story 4 - 会话交互保护与跨平台快捷键一致 (Priority: P2)

无论用户使用的是 Windows 还是 macOS 桌面端，或在自行编辑正文、拖动布局与核对引用期间刚好遇到 AI 后台完成建图/改图并触发自动跳转，用户的未保存修改与当前定位都不会静默丢失，画布级快捷键在不同桌面平台上保持一致可用。

**Why this priority**: 这些属于高频隐蔽交互缺陷：虽然不直接让宿主崩溃，但会导致编辑中并发跳转丢稿/误清引用，以及 macOS 平台下画布撤销/重做快捷键失效。

**Independent Test**: 分别在 macOS 键盘修饰键环境以及“正在编辑/拖动布局/核对引用时触发自动跳图或引用打开”条件下执行编辑、撤销、保存与跳转操作，验证修改与引用状态受保护、快捷键生效。

**Acceptance Scenarios**:

1. **Given** 用户正在画布中拖动节点调整布局、正在正文编辑器中输入内容，或正在核对某条引用定位，**When** 后台会话刚完成自动建图或改图并触发自动跳图通知，**Then** 系统不强行切走当前画面、不丢弃拖拽或输入草稿，也不清空当前引用定位，而是显示非阻塞的轻量通知并提供手动“查看更新”入口；仅当用户处于空闲浏览且目标不同于当前画面时自动打开，且用户主动触发的所有外部切图或引用跳转均经过统一的未保存变更保护流程。
2. **Given** 用户在 macOS 平台上浏览画布并打开侧栏，**When** 用户使用平台标准主修饰键执行画布撤销与重做，**Then** 撤销和重做行为与搜索快捷键一样能正确响应平台主修饰键，与 Windows 保持一致体验。

### User Story 5 - 路径规范化与工具异常语义对齐 (Priority: P3)

在大小写不敏感的文件系统环境（如 Windows）下，来自不同宿主入口的工作区路径即使在大小写或末尾分隔符格式上存在微小差异，系统也能识别为同一工作区并保证串行控制与访问一致；当 AI 调用插件工具遇到校验失败、版本冲突或权限拒绝时，工具能以宿主认可的失败状态返回，便于宿主与调用方准确识别执行结果。

**Why this priority**: 消除路径比对盲区和宿主层错误状态误判，提高系统在跨入口和异常路径下的严谨度。

**Independent Test**: 在 Windows 环境下分别以不同大小写和末尾斜杠形式传入同一工作区路径进行读取、保存与引用跳转，验证不误报“工作区已变化”且并发队列串行有效；触发一次合法的校验失败工具调用，验证宿主收到的工具执行结果状态为失败而非成功。

**Acceptance Scenarios**:

1. **Given** 宿主不同服务对同一 Windows 工作区传入了盘符大小写或末尾斜杠不同的路径，**When** 插件执行读写串行锁定、工作区一致性校验或引用回跳校验，**Then** 系统将其识别为同一工作区并正常放行与串行化，不误报“工作区已变化”。
2. **Given** AI 调用插件工具因参数无效、权限受限或版本冲突未能成功保存，**When** 工具将结果返回给宿主与模型，**Then** 宿主层面能准确识别该次工具调用为失败状态，同时模型仍能获得清晰的结构化诊断信息以决定重试或停手。

---

### Edge Cases

- **宿主升级后部分契约字段缺失或变更**: 若新版宿主在工具注册、技能注册或侧栏事件流中新增严格校验或调整非核心事件结构，插件能拒绝静默破坏并只停用受影响子功能，同时输出可定位的诊断信息。
- **批量永久删除部分成功后的并发中断**: 若 3 张导图中有 2 张文件已删但目录索引因版本冲突未能更新，重试永久删除或刷新目录时系统能平滑接续并完成收敛，而不是因 `map.json` 已不存在而报错拒绝。
- **大体积图片导图的增量编辑与加载**: 当导图内累计资源接近单次传输限制时，文字编辑与布局保存不应被迫携带全量图片重传或因单次响应过大而失败。
- **频繁切换会话与长期挂机**: 连续切换 20 个不同会话并在每个会话打开不同导图后关闭标签页，已关闭且无未保存草稿的会话资源应被释放，仅保留必要的当前活跃会话与未提交草稿。
- **混合大小写路径引用跨版本重读**: 节点路径仅在大小写上有重复或 Windows 工作区路径在会话重启前后盘符大小写变化时，已有导图与历史引用仍能正常打开并防重。
- **离线 HTML 导出体积与内联字符边界**: 当导图标题、正文或图块包含特殊脚本分隔符或大量图片资源时，导出的离线 HTML 仍可直接在本地安全打开且无脚本截断风险。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 插件清单与构建边界 MUST 对所有直接消费的宿主能力进行完整且兼容的依赖声明，不得对与宿主共享实例的运行期校验库或宿主包钉死互不兼容的精确单点版本，同时不得在打包产物中隐式依赖未声明的宿主外部模块。
- **FR-002**: 插件在宿主侧及客户端侧的初始化与事件订阅（包括工具参数模式转换、远端服务挂载、实时会话事件监听及工具/技能注册）MUST 具备隔离保护与防御性校验，单一子能力初始化失败或遇到非预期宿主事件结构时 MUST 降级处理并记录诊断，不得导致宿主崩溃或主界面不可用。
- **FR-003**: 插件客户端残留的未接入宿主内部事件耦合代码 MUST 清理或通过明确支持的宿主接口替代，不得保留对未公开内部事件的无效依赖。
- **FR-004**: 永久删除导图与更新目录索引之间发生并发版本冲突或部分失败时，系统 MUST 具备状态自愈或可重试收敛机制，保证已删除文件对应的导图条目能从有效列表与回收站正常退场，不陷入无法清理也无法重试的死锁。
- **FR-005**: 对于已完成永久删除或已作废的未完成创建占位目录，系统 MUST 在常规状态下保留其防复活标记，并在接近宿主目录列举上限前给出明确预警，同时支持在用户显式触发清理或超过安全阈值时，按严格归属校验（无未知文件、无活动事务）回收最旧的已完结空目录，防止触及上限阻断整个工作区的导图访问。
- **FR-006**: 当节点笔记不再引用某本地图片资源时，系统 MUST 在当前可撤销编辑会话期间保留该资源以保障撤销与恢复；在编辑会话结束或用户显式触发清理、且确认全图没有任何节点引用该资源后，系统 MUST 安全回收该孤儿资源，避免无效附件长期滞留膨胀。
- **FR-007**: 节点笔记的本地附件支持 MUST 收敛为仅支持受支持格式的本地图片资源，不再内联读取或尝试打开本地 PDF/TXT 等非图片附件；遇到本地非图片链接时 MUST 以明确只读提示展示，不生成触发安全策略拦截的内联链接，也不因此阻塞整张导图阅读。
- **FR-008**: 文件变更监听机制 MUST 对并发打开的观察流数量进行收敛或合并，并在初始化监听就绪时避免触发冗余重复刷新，防止导图和附件数量增多时因监听流过多而频繁报“文件观察不可用”。
- **FR-009**: 导图加载、校验与编辑保存 MUST 避免不必要的全量资源重复读取和超限载荷拼装，对导图整体可承载载荷建立明确的边界检测与提示。
- **FR-010**: 服务端与客户端的内存级状态缓存（包括会话编辑状态、布局草稿、删除预览令牌和已知笔记路径映射）MUST 具备明确的淘汰、清理或数量/时效上限，在会话关闭、导图删除或过期后及时释放内存。
- **FR-011**: 后台工具完成引发的自动跳转在用户正处于正文编辑、布局拖动或引用定位核对状态时 MUST 转为非阻塞轻量通知（提供手动查看入口），不得强行切图、丢弃草稿或清除当前引用定位；在用户空闲浏览且目标不同时方可自动打开，且所有用户触发的外部导航切换（如点击聊天中的引用）MUST 经过统一的未保存变更保护流程。
- **FR-012**: 画布级键盘快捷键（包括撤销/重做与搜索）MUST 统一兼容 Windows/Linux 与 macOS 平台的主修饰键习惯。
- **FR-013**: 工作区路径比较与并发操作串行化标识生成 MUST 根据文件系统语义进行规范化处理（消除路径末尾分隔符及大小写不敏感平台下的盘符/路径大小写差异），且节点路径防重判定在读写两端的规范化规则保持一致。
- **FR-014**: 服务端工具在遇到参数校验错误、版本冲突、权限拒绝或事务失败时，MUST 向宿主正确传达工具执行失败状态，同时保持结构化错误代码与诊断信息供模型和界面消费。

### Key Entities

- **宿主兼容边界（Host Compatibility Boundary）**: 插件向宿主声明的运行引擎范围、共享基础库对齐策略、服务注入清单以及运行时降级隔离策略。
- **目录生命周期状态（Library & Directory Lifecycle）**: 导图在有效列表、回收站、永久删除中、已永久删除及未完成创建作废之间的状态流转，包括与物理目录及孤儿附件清理的同步关系。
- **监听与缓存预算（Watch & Cache Budget）**: 插件允许同时维持的文件监听流范围、单图与总载荷传输上限，以及内存中会话/预览/草稿对象的回收边界。
- **运行上下文环境（Runtime Context）**: 桌面端与本地/HTTPS 安全上下文运行边界、操作系统平台快捷键约定及工作区路径规范化表示。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 当宿主共享基础库或非关键服务在声明的兼容范围内发生变化时，插件启动过程中因依赖版本冲突或未捕获边界异常导致的宿主崩溃率降至 **0**，宿主主对话区 100% 保持可用。
- **SC-002**: 连续执行 100 次“创建失败清理”与“永久删除”操作（含目录并发变更干扰场景）后，导图目录索引与回收站状态 100% 可正常加载与收敛，不出现永久卡死或无法打开列表的情况。
- **SC-003**: 打开包含 50 个导图的目录页或包含 50 个节点与 20 个附件的单张导图时，并发文件观察数量显著收敛（目录页与单图分别不超过受控的小常数上限而非随全量文件成倍线性增长），且不触发因首次建立观察导致的冗余二次刷新。
- **SC-004**: 连续切换 20 个会话并在各会话中编辑、预览删除后关闭页签，内存中残留的已关闭且无未保存草稿的会话对象与过期预览记录清理率为 **100%**。
- **SC-005**: 在 Windows 与 macOS 桌面端（及本地/HTTPS 安全上下文）环境下，编辑保存、画布撤销/重做与引用回跳的核心流程均可正常完成，本地非图片链接给出清晰只读提示，无静默无响应或未捕获崩溃。

## Assumptions

- **兼容目标与边界**: 插件继续保持与宿主 DSH 原生侧栏、原生工具和原生 Skill 体系对接，不绕过宿主沙箱或文件权限体系；对于已公布的 `0.2.2-alpha.3` ~ `0.2.x` 范围继续保持向后兼容，并为未来小版本演进留出防御隔离空间。
- **非安全上下文明确不纳入支持**: 插件仅面向桌面端以及本地/HTTPS 安全上下文运行，不支持通过局域网或移动端非加密 HTTP 远程访问场景，不为此类环境添加额外加密回退实现。
- **目录与资源清理安全前提**: 任何物理目录或孤儿附件的自动/手动清理仍必须严格遵守现有项目宪章原则（不删除未知用户文件、不静默覆盖外部冲突、不递归盲删不可识别目录），只在插件可证明归属且已脱离引用的前提下进行。
- **本轮完整交付范围**: 本轮 `009` 规范与后续实施一次性覆盖全部 P1–P3 需求（共 5 个用户故事、14 条功能需求），在实施规划中按 P1 → P2 → P3 优先级拆分可独立验证的任务。
- **工作区路径与大小写**: 在大小写不敏感平台（如 Windows）上按规范化路径视为同一工作区，在大小写敏感平台（如 Linux）上保持区分大小写，仅规范化多余分隔符与末尾斜杠。
